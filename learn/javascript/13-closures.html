Medium questions (14)

Q1. medium

What is a closure?

function outer() {
  const msg = "hi";
  return () => msg;    // closure over msg
}
console.log(outer()());   // "hi"
  1. A A function that remembers variables from the scope where it was CREATED, even after that scope has finished
  2. B A function that closes the browser
  3. C A way to end a loop
  4. D A private class method

Answer: A — A function that remembers variables from the scope where it was CREATED, even after that scope has finished

When an inner function references an outer variable and outlives the outer call, JavaScript keeps that variable alive for it. Closures are the foundation of callbacks, modules and React hooks.

Q2. medium

  1. A 10 - the closure keeps x alive after outer() returned
  2. B undefined
  3. C ReferenceError
  4. D 0

Answer: A — 10 - the closure keeps x alive after outer() returned

Normally locals vanish when a function returns, but because the returned function still references x, it is retained in memory.

Q8. medium

What is the module pattern using closures?

const bank = (function() {
  let balance = 0;                       // private
  return {
    deposit(n) { balance += n; },
    getBalance() { return balance; }
  };
})();
bank.deposit(100);
console.log(bank.balance);   // undefined - private!
  1. A An IIFE that keeps variables private and returns only the public methods
  2. B Importing files
  3. C A class
  4. D A loop pattern

Answer: A — An IIFE that keeps variables private and returns only the public methods

Before ES modules, this was the standard way to get privacy: internal state lives in the closure and only the returned object is reachable.

Q16. medium

  2. B No, memory is freed immediately

Q14. hard

What is memoization, and how do closures enable it?

function memoize(fn) {
  const cache = {};
  return n => {
    if (n in cache) return cache[n];
    return (cache[n] = fn(n));
  };
}
  1. A Caching results in a closure-held object so repeated calls with the same input return instantly
  2. B Writing memos in comments
  3. C Freeing memory
  4. D Sorting cached data

Answer: A — Caching results in a closure-held object so repeated calls with the same input return instantly

The cache lives in the closure - private, persistent between calls, and invisible to callers.

Q22. hard

Why is this a common React-hooks pitfall (stale closure)? useEffect(() => { const id = setInterval(() => setCount(count + 1), 1000); }, []);

  1. A The effect captured count from the FIRST render, so it always adds 1 to that stale value
  2. B setInterval is not allowed
  3. C The syntax is wrong
  4. D It works correctly

Answer: A — The effect captured count from the FIRST render, so it always adds 1 to that stale value

With an empty dependency array the callback closes over the initial count forever. The fix is the functional updater: setCount(c => c + 1), which does not depend on the captured value.
