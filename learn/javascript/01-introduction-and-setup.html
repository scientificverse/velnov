Easy questions (15)

Q1. easy

What is JavaScript mainly used for?

  1. A Making web pages interactive - and also servers, apps and games
  2. B Styling web pages only
  3. C Structuring web page content only
  4. D Managing databases only

Answer: A — Making web pages interactive - and also servers, apps and games

HTML gives structure, CSS gives style, and JavaScript adds behaviour: reacting to clicks, updating content, fetching data. With Node.js it also runs servers, and it powers mobile and desktop apps too.

  • The three web languages: HTML = structure, CSS = looks, JS = behaviour.

Q2. easy

Is JavaScript the same language as Java?

  1. A No - completely different languages with similar names
  2. B Yes, JavaScript is a version of Java
  3. C JavaScript is Java for browsers
  4. D Java is compiled JavaScript

Answer: A — No - completely different languages with similar names

They are unrelated. JavaScript was named for marketing reasons when Java was popular in 1995. A famous line: 'Java is to JavaScript what car is to carpet'.

Q9. medium

Where is the RECOMMENDED place to put a <script> tag that manipulates the page?

<head>
  <script src="app.js" defer></script>
</head>
<!-- or -->
  <script src="app.js"></script>
</body>
  1. A Just before </body>, or in <head> with the defer attribute
  2. B Always at the very top of <head> with no attributes
  3. C Inside the <title> tag
  4. D Anywhere - position never matters

Answer: A — Just before </body>, or in <head> with the defer attribute

Scripts run as the browser reaches them. A plain script in <head> runs BEFORE the HTML elements exist, so document.querySelector() finds nothing. Putting it before </body> (or using defer) guarantees the page is ready.

deferasyncDOM ready

Q10. medium

What does the defer attribute do? <script src="app.js" defer></script>

  1. A Downloads the script in parallel but runs it only after the HTML is fully parsed
  2. B Delays the script by 5 seconds
  3. C Stops the script from ever running
  4. D Runs the script before the HTML

Answer: A — Downloads the script in parallel but runs it only after the HTML is fully parsed

defer keeps HTML parsing uninterrupted, then executes the script once the document is ready - best of both worlds. async also downloads in parallel but runs as soon as it arrives, in unpredictable order.

Q12. medium

Are semicolons required at the end of statements?

let b = 2;   // explicit semicolons - safest for beginners
  1. A Not strictly - JavaScript inserts them automatically (ASI) - but writing them is safer and common
  2. B Yes, always, or the code fails
  3. C Never allowed
  4. D Only inside functions

Answer: A — Not strictly - JavaScript inserts them automatically (ASI) - but writing them is safer and common

Automatic Semicolon Insertion adds them for you in most cases, but it occasionally guesses wrong (especially before lines starting with ( or [). Many teams write them; some styles omit them deliberately. Be consistent.

Q18. medium

What does 'JavaScript is an interpreted (JIT-compiled) language' mean?

  1. A The engine reads and runs your source directly - no separate compile step for you
  2. B You must compile it to .exe first
  3. C It only runs on interpreters you install
  4. D It converts to Java bytecode

Answer: A — The engine reads and runs your source directly - no separate compile step for you

You write .js and the browser engine (V8 in Chrome, SpiderMonkey in Firefox) executes it immediately. Modern engines use Just-In-Time compilation internally for speed, but you never run a compiler yourself.

Q19. medium

What is ECMAScript (ES)?

  1. A The official standard that JavaScript implements - ES6/ES2015 was a major update
  2. B A JavaScript framework
  3. C A browser
  4. D A rival language

Answer: A — The official standard that JavaScript implements - ES6/ES2015 was a major update

ECMAScript is the specification; JavaScript is its best-known implementation. ES6 (2015) introduced let/const, arrow functions, classes, promises and template literals. Yearly updates continue (ES2020, ES2021...).

Q22. medium

In what order does the browser execute the lines of a script?

  1. A Top to bottom, one statement at a time (single-threaded)
  2. B Random order
  3. C All lines at once in parallel
  4. D Bottom to top

Answer: A — Top to bottom, one statement at a time (single-threaded)

JavaScript is single-threaded: statements run in order, one at a time. Asynchronous work (timers, network requests) is scheduled and handled later by the event loop - covered in the Async topic.

Q24. medium

Why is keeping JavaScript in a SEPARATE .js file better than writing it inside HTML?

  1. A Reusable across pages, cached by the browser, and keeps structure separate from behaviour
  2. B It runs faster in every case
  3. C Inline JavaScript is not allowed
  4. D It hides the code from users

Answer: A — Reusable across pages, cached by the browser, and keeps structure separate from behaviour

External files can be shared by many pages, cached after the first download, and edited without touching the HTML. This 'separation of concerns' also keeps files readable. (Note: users can still view the code.)

Q27. medium

What does document.write("Hi") do, and why is it discouraged?

Q30. medium

What is the difference between a statement and an expression?

  1. A An expression produces a VALUE (2 + 3); a statement performs an ACTION (let x = 5;)
  2. B They are the same
  3. C Expressions only appear in loops
  4. D Statements always return values

Answer: A — An expression produces a VALUE (2 + 3); a statement performs an ACTION (let x = 5;)

Expressions evaluate to a value and can be nested inside other code. Statements are complete instructions. In 'let y = 2 + 3;', the whole line is a statement and '2 + 3' is an expression.
