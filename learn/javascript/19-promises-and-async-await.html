Medium questions (14)

Q1. medium

What is a Promise?

  1. A An object representing a value that will be available later - a placeholder for an async result
  2. B A guaranteed return value
  3. C A type of callback
  4. D A loop construct

Answer: A — An object representing a value that will be available later - a placeholder for an async result

A promise is a receipt for future data. It lets you attach handlers now for a result that arrives later, avoiding deeply nested callbacks.

PromisesAsync

Q2. medium

What are the three states of a promise?

  1. A Pending, fulfilled, rejected
  2. B Start, middle, end
  3. C Open, closed, error
  4. D Waiting, running, done

Answer: A — Pending, fulfilled, rejected

A promise begins pending and settles exactly once into fulfilled (with a value) or rejected (with a reason). It can never change again.

Promise states

Q3. medium

How do you handle a promise's SUCCESS value?

fetch(url).then(res => res.json()).then(data => show(data));

const data = await (await fetch(url)).json();
  1. A .then(value => ...) or await
  2. B .catch(value => ...)
  3. C .finally(value => ...)
  4. D return value

Answer: A — .then(value => ...) or await

then receives the fulfilled value. await unwraps it more readably inside an async function.

Q4. medium

How do you handle a promise REJECTION?

  1. A .catch(err => ...) or try/catch around await
  2. B .then(err => ...)
  3. C if (promise.error)
  4. D Rejections cannot be handled

Answer: A — .catch(err => ...) or try/catch around await

catch handles rejections anywhere earlier in the chain. With await, the rejection is thrown, so a normal try/catch works.

Q5. medium

What does .finally() do?

setLoading(true);

  1. A Runs whether the promise fulfilled or rejected - ideal for cleanup
  2. B Runs only on success
  3. C Runs only on failure
  4. D Ends the chain permanently

Answer: A — Runs whether the promise fulfilled or rejected - ideal for cleanup

Perfect for hiding a loading spinner or re-enabling a button. It receives no argument and passes the result through unchanged.

Q7. medium

What does an async function ALWAYS return?

  2. B The value directly

Answer: A — A promise - even if you return a plain value

return 42 inside async produces a promise fulfilled with 42. That is why you must await it or use .then() at the call site.

Q8. medium

Where can you use the await keyword?

  1. A Inside an async function, or at the top level of an ES module
  2. B Anywhere
  3. C Only inside loops
  4. D Only in the browser

Answer: A — Inside an async function, or at the top level of an ES module

Using await in a regular function is a SyntaxError. Top-level await works in ES modules (type="module"), not in classic scripts.

Q11. medium

What does Promise.all([p1, p2]) do?

  1. A Waits for ALL to fulfil and gives an array of results - but rejects immediately if ANY rejects
  2. B Waits for the first one
  3. C Runs them one after another
  4. D Ignores rejections

Answer: A — Waits for ALL to fulfil and gives an array of results - but rejects immediately if ANY rejects

It is all-or-nothing: one failure rejects the whole thing (the others still run but their results are discarded). Use allSettled when partial success is acceptable.

Q15. medium

What does each .then() in a chain return?

fetch(url)
  .then(res => res.json())   // returns a promise - awaited
  .then(data => data.items)   // plain value
  .then(items => show(items));
  1. A A NEW promise resolved with the callback's return value - which is why chaining works
  2. B The original promise
  3. C undefined
  4. D The raw value

Answer: A — A NEW promise resolved with the callback's return value - which is why chaining works

Returning a value passes it to the next then; returning a PROMISE waits for it to settle first, flattening the chain automatically.

Q18. medium

How do you catch an error from an awaited promise?

try {
  const data = await getData();
} catch (err) {
  showError(err);
}
  1. A Wrap the await in try/catch
  2. B Use .then only
  3. C Errors cannot be caught with await
  4. D Use if (error)

Answer: A — Wrap the await in try/catch

await converts rejection into a thrown error, so ordinary try/catch/finally works - one of the main readability wins of async/await.

Q21. medium

How do you run async operations SEQUENTIALLY?

  1. A A for...of loop with await inside
  2. B forEach with await
  3. C Promise.all
  4. D map with await

Answer: A — A for...of loop with await inside

for...of respects await, pausing each iteration until the operation completes - necessary when each step depends on the previous or you must not overload a server.

Q26. medium

Why must you await response.json() after fetch?

const res = await fetch(url);
const data = await res.json();
  1. A Reading and parsing the body is itself asynchronous, so json() returns a promise
  2. B It is optional
  3. C To convert to a string
  4. D fetch is synchronous

Answer: A — Reading and parsing the body is itself asynchronous, so json() returns a promise

fetch resolves once the HEADERS arrive; the body may still be streaming. Hence the classic two awaits.

Q29. medium

Can a promise change state twice?

  1. A No - it settles once; later resolve/reject calls are ignored
  2. B Yes, any number of times
  3. C Only from rejected to fulfilled
  4. D Only with .then

Answer: A — No - it settles once; later resolve/reject calls are ignored

Immutability once settled makes promises predictable: every handler attached (before or after) sees the same single outcome.

Q6. hard

How do you create a promise manually?

const sleep = ms => new Promise(resolve => setTimeout(resolve, ms));
  1. A new Promise((resolve, reject) => { ... })
  2. B Promise.create()
  3. C promise()
  4. D new Async()

Answer: A — new Promise((resolve, reject) => { ... })

The executor runs immediately; call resolve(value) on success or reject(error) on failure. Mainly used to wrap old callback APIs.

Promise constructor

Q9. hard

What is the output ORDER? async function f() { console.log("1"); await null; console.log("2"); } f(); console.log("3");

  1. A 1 3 2 - code before await runs synchronously; the rest resumes as a microtask
  2. B 1 2 3
  3. C 3 1 2
  4. D 1 3, then 2 never runs

Answer: A — 1 3 2 - code before await runs synchronously; the rest resumes as a microtask

An async function starts executing immediately and only pauses AT the first await, returning control to the caller. Awaiting even a non-promise defers the remainder.

Q10. hard

What is wrong with this sequential code? const a = await fetchA(); const b = await fetchB();

const [a, b] = await Promise.all([fetchA(), fetchB()]);
  1. A If they are independent, this wastes time - B only starts after A finishes. Use Promise.all
  2. B It is a syntax error
  3. C await cannot be used twice
  4. D Nothing is wrong

Answer: A — If they are independent, this wastes time - B only starts after A finishes. Use Promise.all

Sequential awaits are correct when B needs A's result, but wasteful otherwise. Promise.all runs them concurrently, roughly halving the wait.

How is Promise.allSettled different from Promise.all?

results.forEach(r => r.status === "fulfilled" ? ok(r.value) : bad(r.reason));

Ideal when you want every outcome, e.g. uploading ten files and reporting which succeeded and which failed.

Q14. hard

What does Promise.any() do?

  1. A Fulfils with the FIRST successful promise, ignoring rejections (fails only if all fail)
  2. B Same as race
  3. C Same as all
  4. D Returns any random one

Answer: A — Fulfils with the FIRST successful promise, ignoring rejections (fails only if all fail)

Unlike race (which settles on the first result even if it is an error), any keeps waiting for a success - useful for querying several mirrors.

Q17. hard

Where does an error thrown inside a .then() go?

  1. A To the nearest .catch() LATER in the chain
  2. B To the surrounding try/catch
  3. C It is silently ignored
  4. D It crashes the browser

Answer: A — To the nearest .catch() LATER in the chain

Rejections skip subsequent then handlers until a catch is found. Note a catch placed BEFORE the throwing then cannot catch it - order matters.

Q20. hard

What is wrong with using await inside forEach? items.forEach(async (i) => { await save(i); });

for (const i of items) await save(i);        // sequential
await Promise.all(items.map(i => save(i)));   // concurrent
  1. A forEach ignores the returned promises, so the code continues without waiting
  2. B It is a syntax error
  3. C async cannot be used in callbacks
  4. D Nothing is wrong

Answer: A — forEach ignores the returned promises, so the code continues without waiting

forEach discards return values, so nothing awaits the saves. Use a for...of loop for sequential work, or Promise.all(items.map(...)) for concurrent work.

Q27. hard

What is the promisify pattern?

const getPos = () => new Promise((res, rej) =>
  navigator.geolocation.getCurrentPosition(res, rej));
const pos = await getPos();
  1. A Wrapping a callback-based API in a promise so it can be awaited
  2. B Converting promises to callbacks
  3. C Making code synchronous

Answer: A — Wrapping a callback-based API in a promise so it can be awaited

Legacy APIs (older Node functions, geolocation, some libraries) take callbacks. Wrapping them once lets the rest of your code use async/await.

Q28. hard

Does creating a promise start its work lazily or immediately?

  1. A Immediately - the executor runs as soon as the promise is created, even before .then is attached
  2. B Only when .then is called
  3. C Only when awaited
  4. D Never automatically

Answer: A — Immediately - the executor runs as soon as the promise is created, even before .then is attached

Promises are EAGER. const p = fetch(url) starts the request at once; awaiting later just waits for the already-running work. This is why Promise.all(fns.map(f => f())) runs concurrently.

Eager evaluation

Q30. hard

What is the practical difference between .then chains and async/await?

  1. A They are equivalent - await is syntax over promises, usually more readable for sequential logic
  2. B await is faster
  3. C then is deprecated
  4. D await avoids promises entirely

Answer: A — They are equivalent - await is syntax over promises, usually more readable for sequential logic

Use await for step-by-step flows and try/catch; use .then when composing pipelines or with combinators like Promise.all. Mixing both is fine.
