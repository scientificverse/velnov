Easy questions (2)

Q1. easy

What is type coercion?

console.log("5" + 3);   // "53" - number coerced to string
console.log("5" - 3);   // 2    - string coerced to number
  1. A JavaScript automatically converting a value from one type to another during an operation
  2. B Forcing a variable to keep one type
  3. C Deleting a type
  4. D A syntax error

Answer: A — JavaScript automatically converting a value from one type to another during an operation

When operands have different types, JavaScript silently converts one to match - like turning 5 into "5" for concatenation. Convenient, but the cause of many surprises.

Q2. easy

What is the difference between == and ===?

console.log(5 == "5");    // true
console.log(5 === "5");   // false
  1. A == converts types before comparing (loose); === requires the same type (strict)
  2. B They are identical
  3. C === is slower and deprecated
  4. D == only works with numbers

Answer: A — == converts types before comparing (loose); === requires the same type (strict)

5 == "5" is true (the string is converted). 5 === "5" is false (number vs string). Best practice: always use === unless you deliberately want coercion.

Q3. medium

Which values are FALSY in JavaScript?

if ("") { }       // skipped
if ("0") { }      // runs! non-empty string
if ([]) { }       // runs! empty array is truthy
  1. A false, 0, -0, "", null, undefined, NaN (and 0n)
  2. B Only false
  3. C false, 0 and []
  4. D Everything except true

Answer: A — false, 0, -0, "", null, undefined, NaN (and 0n)

Those are the only falsy values - EVERYTHING else is truthy, including "0", "false", [], {} and negative numbers. Memorising this short list explains most if-statement surprises.

Q9. medium

What does Number("") return?

console.log(Number(""));      // 0
console.log(Number("  "));    // 0
console.log(Number("abc"));   // NaN
  1. A 0 - an empty string converts to zero
  2. B NaN
  3. C undefined
  4. D ""

Answer: A — 0 - an empty string converts to zero

Number("") and Number(" ") are both 0, which surprises people expecting NaN. Number("abc") is NaN. This is why empty form fields can silently become 0.

Q15. medium

What is the output? console.log("10" > "9");

console.log("10" > "9");           // false - string compare
console.log(10 > 9);                // true
console.log("10" > 9);              // true - mixed types convert to number
  1. A false - two strings compare ALPHABETICALLY, and "1" comes before "9"
  2. B true
  3. C NaN
  4. D SyntaxError

Answer: A — false - two strings compare ALPHABETICALLY, and "1" comes before "9"

When both operands are strings, comparison is lexicographic (character by character), not numeric. "10" > "9" is false. Convert first: Number("10") > Number("9") is true.

Q17. medium

What is the safest way to compare two values?

  1. A Use === (and !==) so no hidden conversion happens
  2. B Always use ==
  3. C Use = for comparison
  4. D Convert everything to strings first

Answer: A — Use === (and !==) so no hidden conversion happens

=== compares type and value with no surprises. The single accepted exception is x == null to catch both null and undefined at once.

Q19. medium

How do you safely convert user input "42" to a number?

const n = Number(input);
if (Number.isNaN(n)) {
  alert("Please enter a number");
}
  1. A Number(input) or parseInt(input, 10) - then check with Number.isNaN()
  2. B input.toNumber()
  3. C (int) input
  4. D input * "1"

Answer: A — Number(input) or parseInt(input, 10) - then check with Number.isNaN()

Number() is strict (rejects "42abc"); parseInt(str, 10) reads leading digits. Always pass the radix 10 to parseInt and verify the result is not NaN.

Q23. medium

How can you check whether a value is a real number (not NaN, not a numeric string)?

Number.isFinite(42);      // true
Number.isFinite("42");    // false
Number.isFinite(NaN);     // false
  1. A typeof v === "number" && !Number.isNaN(v) (or Number.isFinite(v))
  2. B typeof v === "number" only
  3. C v > 0
  4. D isNaN(v) === false

Answer: A — typeof v === "number" && !Number.isNaN(v) (or Number.isFinite(v))

typeof alone accepts NaN (whose type is "number"). Number.isFinite(v) is the neat one-call version - it rejects NaN, Infinity and non-numbers.

JSON.parse turns text into objects (used on API responses); JSON.stringify does the reverse (used before sending or storing data).

Q27. medium

Which comparison is safe for checking if a variable exists and has a value?

  1. A if (value != null) - catches both null and undefined
  2. B if (value) - also rejects 0 and ""
  3. C if (value !== false)
  4. D if (typeof value)

Answer: A — if (value != null) - catches both null and undefined

if (value) rejects legitimate values like 0 and "". value != null (the one accepted use of loose equality) checks only for null/undefined. Modern alternative: value ?? fallback.

Q29. medium

What does Object.is(NaN, NaN) return?

console.log(Object.is(NaN, NaN));   // true
console.log(NaN === NaN);            // false
console.log(Object.is(0, -0));       // false
  1. A true - Object.is treats NaN as equal to itself, unlike ===
  2. B false
  3. C NaN
  4. D undefined

Answer: A — true - Object.is treats NaN as equal to itself, unlike ===

Object.is is like === with two fixes: NaN equals NaN, and +0 is NOT equal to -0. Useful for precise value comparison.

Q4. hard

What is the output? console.log(Boolean([]), Boolean({}));

if (arr.length === 0) { }              // correct emptiness test
if (Object.keys(obj).length === 0) { }
  1. A true true - empty arrays and objects are TRUTHY
  2. B false false
  3. C true false
  4. D false true

Answer: A — true true - empty arrays and objects are TRUTHY

Any object - including an empty array or object - is truthy. To test emptiness check arr.length === 0 or Object.keys(obj).length === 0.

  • This trips up people coming from Python, where [] is falsy.

Q5. hard

What is the output? console.log([] == false);

console.log([] == false);    // true  (coerced)
console.log(Boolean([]));    // true  (truthy)
console.log([] === false);   // false (strict)
  1. A true - [] converts to "" then to 0, and false converts to 0
  2. B false
  3. C undefined
  4. D TypeError

Answer: A — true - [] converts to "" then to 0, and false converts to 0

Loose equality converts both sides to numbers: [] becomes "" becomes 0, and false becomes 0. So 0 == 0 is true - even though Boolean([]) is true! A perfect argument for using ===.

Q6. hard

What is the output? console.log("" == 0, "0" == 0, "" == "0");

  1. A true true false - == converts strings to numbers, but "" and "0" are different strings
  2. B true true true
  3. C false false false
  4. D false true false

Answer: A — true true false - == converts strings to numbers, but "" and "0" are different strings

"" converts to 0 (true), "0" converts to 0 (true), but comparing two STRINGS does no numeric conversion, so "" == "0" is false. Loose equality is not transitive - a classic demonstration of why to avoid it.

Q12. hard

What is the output? console.log([] + []);

console.log(typeof ([] + []));   // "string"
console.log([1,2] + [3]);        // "1,23"
  1. A "" (an empty string) - both arrays convert to empty strings and concatenate
  2. B []
  3. C 0
  4. D NaN

Answer: A — "" (an empty string) - both arrays convert to empty strings and concatenate

The + operator converts objects to primitives; an array becomes its join(",") string, so [] becomes "". Empty + empty = empty string. The result is a string, not an array.

Q16. hard

Why does [10, 9, 100].sort() give [10, 100, 9]?

console.log([10, 9, 100].sort());              // [10, 100, 9]
console.log([10, 9, 100].sort((a,b) => a-b));   // [9, 10, 100]
  1. A sort() converts elements to STRINGS by default and sorts alphabetically
  2. B sort() is broken
  3. C It sorts by length
  4. D It sorts randomly

Answer: A — sort() converts elements to STRINGS by default and sorts alphabetically

The default sort compares string forms: "10" < "100" < "9". For numbers you must pass a comparator: sort((a, b) => a - b).

  • One of the most common real-world JavaScript bugs.

Q18. hard

What is the output? console.log("5" === 5, "5" == 5);

  1. A false true
  2. B true true
  3. C false false

Answer: A — false true

Strict comparison fails because the types differ. Loose comparison converts the string to a number first, so it succeeds. Data from input fields and APIs is often a string - a frequent source of this bug.

Q20. hard

What is the output? console.log(0.1 + 0.2 === 0.3);

console.log(0.1 + 0.2);   // 0.30000000000000004
console.log(Math.abs(0.1 + 0.2 - 0.3) < Number.EPSILON);   // true
  1. A false - floating-point maths gives 0.30000000000000004
  2. B true
  3. C NaN
  4. D SyntaxError

Answer: A — false - floating-point maths gives 0.30000000000000004

Binary floating point cannot represent 0.1 and 0.2 exactly. Compare with a tolerance: Math.abs(a - b) < Number.EPSILON, or work in integers (cents instead of rupees).

Q30. hard

Why should you write === almost everywhere, in one sentence?

  1. A It compares without hidden conversions, so results are predictable and bug-free
  2. B It is faster to type
  3. C == was removed from the language
  4. D === works on more types

Answer: A — It compares without hidden conversions, so results are predictable and bug-free

Loose equality follows a complex conversion table that is not even transitive ("" == 0 and "0" == 0, but "" != "0"). Strict equality has one simple rule: same type, same value. Linters flag == for this reason.
