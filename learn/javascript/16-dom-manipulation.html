Easy questions (2)

Q1. easy

What is the DOM?

  1. A A tree of objects representing the HTML page, which JavaScript can read and change
  2. B A JavaScript library
  3. C A CSS feature
  4. D A type of database

Answer: A — A tree of objects representing the HTML page, which JavaScript can read and change

Document Object Model: the browser parses your HTML into a live object tree. Changing the DOM instantly changes what the user sees.

DOMdocument

Q2. easy

Which method selects the FIRST element matching a CSS selector?

document.querySelector("#title");
document.querySelector(".card .btn");
document.querySelectorAll("li");
  1. A document.querySelector(".box")
  2. B document.getElement(".box")
  3. C document.find(".box")
  4. D document.select(".box")

Answer: A — document.querySelector(".box")

querySelector accepts any CSS selector and returns the first match (or null). querySelectorAll returns all matches as a NodeList.

querySelectorSelectors

Q3. medium

What does querySelector return when nothing matches?

const el = document.querySelector(".missing");
if (el) el.textContent = "hi";
el?.classList.add("on");
  1. A null
  2. B undefined
  3. C An empty array
  4. D An error

Answer: A — null

It returns null, so accessing a property on it throws 'Cannot read properties of null' - the most common DOM error. Check first or use optional chaining.

What is the difference between getElementById and querySelector?

  2. B They are identical
  3. C querySelector only works on classes
  4. D getElementById returns an array

Answer: A — getElementById takes a bare id (no #) and is slightly faster; querySelector takes any CSS selector

getElementById("title") vs querySelector("#title"). The speed difference is negligible in practice; querySelector's flexibility usually wins.

Q6. medium

How do you change the visible TEXT of an element safely?

  1. A el.textContent = "Hello"
  2. B el.value = "Hello"
  3. C el.text = "Hello"
  4. D el.write("Hello")

Answer: A — el.textContent = "Hello"

textContent sets plain text and escapes any HTML - safe against injection. innerText is similar but slower (it respects CSS visibility).

Q11. medium

How do you change an inline style?

el.style.backgroundColor = "red";
el.style.fontSize = "20px";
  1. A el.style.backgroundColor = "red" (camelCase property names)
  2. B el.style.background-color = "red"
  3. C el.css("background-color", "red")
  4. D el.setStyle("background", "red")

Answer: A — el.style.backgroundColor = "red" (camelCase property names)

CSS hyphenated names become camelCase in JavaScript because background-color would be parsed as subtraction. Prefer toggling classes over many inline styles.

Q12. medium

How do you create a new element and add it to the page?

Answer: A — const li = document.createElement("li"); parent.appendChild(li);

createElement builds a detached element; it appears only once inserted with appendChild, append, prepend or insertBefore.

Q13. medium

What is the difference between append() and appendChild()?

  1. A append() accepts multiple nodes AND plain strings; appendChild() takes exactly one node and returns it
  2. B They are identical
  3. C appendChild is newer
  4. D append only works on text

Answer: A — append() accepts multiple nodes AND plain strings; appendChild() takes exactly one node and returns it

append is the modern, more flexible method: parent.append(el, "text", el2). appendChild remains widely used and returns the appended node.

Q16. medium

What is the difference between setAttribute and setting a property?

  1. A setAttribute changes the HTML attribute; properties reflect the CURRENT state (they can diverge, e.g. input.value)
  2. B They are identical
  3. C setAttribute is deprecated
  4. D Properties do not exist

Answer: A — setAttribute changes the HTML attribute; properties reflect the CURRENT state (they can diverge, e.g. input.value)

After a user types, input.value shows the typed text while getAttribute("value") still shows the original HTML default. Use properties for live state.

Q23. medium

What does insertAdjacentHTML("beforeend", html) do?

  2. B Replaces all content
  3. C Deletes the element

Answer: A — Inserts HTML at a precise position without destroying existing children/listeners

Hard questions (7)

Q5. hard

What is the difference between an HTMLCollection (getElementsByClassName) and a NodeList (querySelectorAll)?

  1. A HTMLCollection is LIVE (updates automatically); querySelectorAll's NodeList is a static snapshot
  2. B They are the same
  3. C NodeList is live
  4. D HTMLCollection is an array

Answer: A — HTMLCollection is LIVE (updates automatically); querySelectorAll's NodeList is a static snapshot

A live collection reflects later DOM changes, which can cause surprising loop behaviour. Static NodeLists are predictable and support forEach.

NodeListLive collections

Q7. hard

Why is innerHTML risky with user-supplied data?

el.textContent = userInput;   // safe
el.innerHTML = userInput;      // dangerous!
  1. A It parses the string as HTML, allowing script/event injection (XSS)
  2. B It is slower only
  3. C It does not work in modern browsers
  4. D It is not risky

Answer: A — It parses the string as HTML, allowing script/event injection (XSS)

Inserting untrusted input via innerHTML lets attackers run code in your users' browsers. Use textContent for text; sanitise if HTML is genuinely required.

XSSSecurity

Q17. hard

Why should you avoid updating the DOM inside a long loop?

const frag = document.createDocumentFragment();
items.forEach(t => { const li = document.createElement("li"); li.textContent = t; frag.append(li); });
list.append(frag);   // one DOM update
  1. A Each change can force reflow/repaint - build the content first, then insert once
  2. B Loops cannot touch the DOM
  3. C It causes syntax errors
  4. D There is no problem

Answer: A — Each change can force reflow/repaint - build the content first, then insert once

A thousand appendChild calls means a thousand layout recalculations. Build an HTML string or a DocumentFragment and insert it in one operation.

PerformanceDocumentFragment

Q24. hard

What is wrong with el.innerHTML += "<li>x</li>" in a loop?

  1. A It re-parses ALL the HTML each time and destroys existing elements' event listeners
  2. B It is a syntax error
  3. C It only adds text
  4. D Nothing is wrong

Answer: A — It re-parses ALL the HTML each time and destroys existing elements' event listeners

The += reads, concatenates and re-writes the entire subtree, which is slow and replaces existing nodes with new ones (losing listeners and input state).

innerHTMLPerformance
