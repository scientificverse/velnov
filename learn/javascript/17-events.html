Easy questions (1)

Q1. easy

What is the modern way to react to a click?

btn.addEventListener("click", () => console.log("clicked"));
  1. A btn.addEventListener("click", handler)
  2. B btn.onClick = handler
  3. C btn.click(handler)
  4. D btn.on("click", handler)

Answer: A — btn.addEventListener("click", handler)

addEventListener allows MULTIPLE handlers for the same event and supports options like once and capture. The onclick property allows only one handler.

Q3. medium

What is the event object passed to a handler?

btn.addEventListener("click", (e) => {
  console.log(e.type, e.target, e.clientX);
});
  1. A An object describing what happened - target, type, coordinates, key pressed, etc.
  2. B The element only
  3. C A string
  4. D Nothing is passed

Answer: A — An object describing what happened - target, type, coordinates, key pressed, etc.

Every handler receives the event as its first argument (conventionally e or event), carrying details and control methods like preventDefault.

Q5. medium

What does e.preventDefault() do?

form.addEventListener("submit", (e) => {
  e.preventDefault();   // stop page reload
  sendData();
});
  1. A Stops the browser's default action - e.g. a form submitting or a link navigating
  2. B Stops the event bubbling
  3. C Removes the listener
  4. D Prevents all events

Answer: A — Stops the browser's default action - e.g. a form submitting or a link navigating

Essential for handling forms with JavaScript, since without it the page reloads and your code appears to do nothing.

preventDefaultForms

Q6. medium

What does e.stopPropagation() do?

  1. A Prevents the event from continuing to bubble up to ancestor elements
  2. B Stops the default action
  3. C Deletes the event
  4. D Cancels all listeners on the page

Answer: A — Prevents the event from continuing to bubble up to ancestor elements

Useful when an inner element's click should not also trigger a parent's handler (e.g. clicking inside a modal should not close it). Use sparingly - it can make behaviour hard to trace.

Q10. medium

Why does event delegation work for elements added dynamically?

  1. A The listener is on the parent, which already exists - new children bubble to it automatically
  2. B The browser re-scans listeners
  3. C It does not work for new elements
  4. D JavaScript adds listeners automatically

Answer: A — The listener is on the parent, which already exists - new children bubble to it automatically

Directly attached listeners only cover elements present at the time. Delegation solves the common bug where newly created buttons stop responding.

Q11. medium

How do you REMOVE an event listener?

function onClick() { }
btn.addEventListener("click", onClick);
btn.removeEventListener("click", onClick);   // works
  1. A removeEventListener with the SAME function reference used to add it
  2. B removeEventListener("click")
  3. C el.listeners = []
  4. D delete el.onclick

Answer: A — removeEventListener with the SAME function reference used to add it

An anonymous inline arrow cannot be removed because you have no reference to it. Store the function in a variable if you plan to remove it.

removeEventListenerCleanup

Q12. medium

What does the { once: true } option do?

  1. A The listener fires at most once, then removes itself automatically
  2. B It fires once per second
  3. C It only works on one element
  4. D Nothing

Answer: A — The listener fires at most once, then removes itself automatically

Ideal for one-time actions like an intro animation or a single-submit guard - no manual cleanup needed.

Q13. medium

Which event fires as the user TYPES in an input?

search.addEventListener("input", (e) => filter(e.target.value));
  1. A input - it fires on every change, including paste
  2. B change - only when leaving the field
  3. C keypress only
  4. D submit

Answer: A — input - it fires on every change, including paste

Use input for live search or character counters. change fires only after the value is committed (blur or selection), which is better for selects and checkboxes.

Q14. medium

How do you detect which key was pressed?

input.addEventListener("keydown", (e) => {
  if (e.key === "Enter") submit();
});
  1. A e.key - a readable string like "Enter", "a", "ArrowUp"
  2. B e.keyCode only
  3. C e.char
  4. D e.button

Answer: A — e.key - a readable string like "Enter", "a", "ArrowUp"

e.key is the modern, readable property. e.keyCode is deprecated. Use e.code when you need the physical key regardless of layout.

Q15. medium

What is the difference between keydown and keyup?

  1. A keydown fires when the key goes DOWN (and repeats if held); keyup fires on release
  2. B They are identical
  3. C keyup fires first
  4. D keydown only works for letters

Answer: A — keydown fires when the key goes DOWN (and repeats if held); keyup fires on release

Use keydown for shortcuts and to preventDefault before the character appears; use keyup when you need the final state after the key is released.

Q17. medium

What is the difference between mouseover and mouseenter?

  1. A mouseover BUBBLES and re-fires when moving over children; mouseenter fires once for the element itself
  2. B They are identical
  3. C mouseenter bubbles
  4. D mouseover works only on links

Answer: A — mouseover BUBBLES and re-fires when moving over children; mouseenter fires once for the element itself

mouseenter/mouseleave are usually what you want for hover effects, because mouseover fires repeatedly as the pointer crosses child elements.

Which event should you use to run code after the page's HTML is ready?

  1. A DOMContentLoaded
  2. B click
  3. C resize
  4. D beforeunload

Answer: A — DOMContentLoaded

DOMContentLoaded fires as soon as the DOM is parsed. Alternatively, adding defer to your script tag achieves the same effect without a listener.

Q2. hard

What is wrong here? btn.addEventListener("click", handleClick());

btn.addEventListener("click", handleClick);          // correct
btn.addEventListener("click", () => handleClick(5));  // with args
  1. A The parentheses CALL handleClick immediately and register its return value instead of the function
  2. B Nothing is wrong
  3. C The event name is wrong
  4. D It needs three arguments

Answer: A — The parentheses CALL handleClick immediately and register its return value instead of the function

Pass the function itself (no parentheses). If you must pass arguments, wrap it: () => handleClick(id).

Q4. hard

What is the difference between e.target and e.currentTarget?

  1. A target is the element that ACTUALLY triggered the event; currentTarget is the element the listener is attached to
  2. B They are always the same
  3. C currentTarget is the parent
  4. D target is always the document

Answer: A — target is the element that ACTUALLY triggered the event; currentTarget is the element the listener is attached to

Clicking a <span> inside a button makes target the span but currentTarget the button. This distinction is the key to event delegation.

Q7. hard

What is event BUBBLING?

  1. A An event fires on the target, then travels UP through each ancestor, triggering their handlers
  2. B Events go downward from document
  3. C Events repeat
  4. D Events fire twice

Answer: A — An event fires on the target, then travels UP through each ancestor, triggering their handlers

Click a button inside a div inside body: handlers fire on the button, then the div, then body, then document. Bubbling is what makes delegation possible.

BubblingPropagation

Q8. hard

What are the three phases of event propagation?

el.addEventListener("click", fn, true);   // capture phase
  1. A Capturing (down), target, then bubbling (up)
  2. B Start, middle, end
  3. C Click, hold, release
  4. D Only bubbling exists

Answer: A — Capturing (down), target, then bubbling (up)

The event descends from document to the target (capture), fires at the target, then bubbles back up. Passing true (or {capture: true}) to addEventListener runs your handler during the capture phase.

CapturingBubbling

What is event DELEGATION?

list.addEventListener("click", (e) => {

  1. A Attaching ONE listener to a parent and using e.target to handle events from many children

Instead of a listener per row, put one on the container. It uses less memory and automatically covers elements added LATER - the standard pattern for dynamic lists.

Q18. hard

What is the output order? parent.addEventListener("click", () => console.log("parent")); child.addEventListener("click", () => console.log("child")); // user clicks child

  1. A child then parent - the event bubbles upward
  2. B parent then child
  3. C Only child
  4. D Only parent

Answer: A — child then parent - the event bubbles upward

Default listeners run in the bubbling phase, starting at the target. Adding {capture: true} to the parent would make it fire FIRST instead.

Q20. hard

Why should scroll and resize handlers be throttled or debounced?

  1. A They fire extremely often, so heavy work in them causes janky, slow scrolling
  2. B They are disabled by default
  3. C They only fire once
  4. D No reason

Answer: A — They fire extremely often, so heavy work in them causes janky, slow scrolling

Scroll can fire dozens of times per second. Throttle limits the rate; debounce waits for a pause. For visibility detection, IntersectionObserver is better still.

Q25. hard

What does e.stopImmediatePropagation() add over stopPropagation()?

  1. A It also prevents OTHER listeners on the SAME element from running
  2. B Nothing extra
  3. C It removes the listener
  4. D It prevents the default action

Answer: A — It also prevents OTHER listeners on the SAME element from running

stopPropagation only halts the journey to ancestors; remaining handlers on the same element still fire. stopImmediatePropagation stops those too.

Propagation control

Q27. hard

Why might a listener attached in a loop capture the wrong value? for (var i = 0; i < 3; i++) btns[i].addEventListener("click", () => console.log(i));

  1. A var creates ONE shared binding, so every handler logs 3 - use let
  2. B Listeners cannot be added in loops
  3. C btns is undefined
  4. D It works correctly

Answer: A — var creates ONE shared binding, so every handler logs 3 - use let

The same closure trap as with setTimeout. Changing var to let gives each iteration its own binding, so the handlers log 0, 1 and 2.

Q29. hard

Why remove event listeners when destroying a component?

const ac = new AbortController();

Answer: A — Listeners keep references alive, preventing garbage collection - a memory leak

Especially for listeners on window/document that reference removed elements. React's useEffect cleanup and AbortController exist for exactly this.
