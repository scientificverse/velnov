Q1. easy

What is the output of: print([x * 2 for x in range(3)])

print([x * 2 for x in range(3)])   # [0, 2, 4]
  1. A [0, 2, 4]
  2. B [2, 4, 6]
  3. C [0, 1, 2]
  4. D [0, 2, 4, 6]

Answer: A — [0, 2, 4]

A list comprehension applies the expression (x * 2) to every value of x in range(3) = 0, 1, 2 -> [0, 2, 4].

Q2. easy

Which ordinary loop is equivalent to: squares = [x**2 for x in nums]

# comprehension:
squares = [x**2 for x in nums]

# equivalent loop:
squares = []
for x in nums:
    squares.append(x**2)
  1. A squares = []\nfor x in nums:\n squares.append(x**2)
  2. B for x in nums: squares = x**2
  3. C squares = for x in nums: x**2

Answer: A — squares = []\nfor x in nums:\n squares.append(x**2)

A comprehension is exactly a build-a-list loop compressed to one line: create empty list, loop, append the expression. Same result, less code.

Q17. easy

What is the main reason to use a comprehension instead of a loop?

  1. A It's the only way to build lists
  2. B Shorter, clearer 'build a list from a list' code (and often slightly faster)
  3. C It uses no memory at all
  4. D Loops are deprecated

Answer: B — Shorter, clearer 'build a list from a list' code (and often slightly faster)

For simple transform/filter operations, one readable line beats four. But if the logic needs multiple steps or side effects, a normal loop is clearer - don't force everything into a comprehension.

Q10. medium

What is (x**2 for x in range(3)) - with PARENTHESES?

gen = (x**2 for x in range(3))
print(gen)         # <generator object ...>
print(list(gen))   # [0, 1, 4]
  1. A A tuple comprehension
  2. B A generator expression - values are produced lazily, one at a time
  3. C A syntax error
  4. D The same as a list comprehension

Answer: B — A generator expression - values are produced lazily, one at a time

Parentheses make a GENERATOR expression: nothing is computed until you iterate it, and values are produced one by one - using almost no memory. There is no 'tuple comprehension'; use tuple(...) to get a tuple.

Q16. medium

  1. A [0, 2, 4, 6]
  2. B [0, 4]
  3. C [2, 6]
  4. D [0, 2]

Answer: B — [0, 4]

First the filter keeps even x (0 and 2), then the expression doubles them -> [0, 4]. Filter first, transform second.

Q7. hard

Where does if-ELSE go in a comprehension? result = [x if x > 0 else 0 for x in nums]

nums = [3, -1, 5]
print([x if x > 0 else 0 for x in nums])  # [3, 0, 5] - transform
print([x for x in nums if x > 0])           # [3, 5]    - filter
  1. A BEFORE the for - because with else it's a conditional EXPRESSION, not a filter
  2. B After the for, like a filter
  3. C if-else is not allowed in comprehensions
  4. D Either position works

Answer: A — BEFORE the for - because with else it's a conditional EXPRESSION, not a filter

Two different ifs! A filtering if (no else) goes AFTER the for and drops items. A conditional expression (with else) goes BEFORE the for and transforms every item. [x if x > 0 else 0 ...] keeps all items, replacing negatives with 0.

  • [x for x in nums if x > 0 else 0] is a SyntaxError.

Ternary expressionFiltering

Q11. hard

Why prefer sum(x*x for x in range(10**7)) over sum([x*x for x in range(10**7)])?

total = sum(x*x for x in range(10**7))  # memory-friendly
  1. A The first is shorter to type only
  2. B The generator version never builds a 10-million-item list in memory - values stream one by one
  3. C The list version gives a wrong answer
  4. D There is no difference

Answer: B — The generator version never builds a 10-million-item list in memory - values stream one by one

The list comprehension materializes ALL 10 million squares in RAM before summing. The generator produces each value, hands it to sum(), and forgets it - constant memory. For large data, generators win.

Q14. hard

How do you FLATTEN matrix = [[1, 2], [3, 4]] into [1, 2, 3, 4] with a comprehension?

matrix = [[1, 2], [3, 4]]
flat = [x for row in matrix for x in row]
print(flat)   # [1, 2, 3, 4]
  1. A [x for row in matrix for x in row]
  2. B [x for x in row for row in matrix]
  3. C [matrix for row in x]
  4. D flatten(matrix)

Answer: A — [x for row in matrix for x in row]

Read the for clauses LEFT TO RIGHT like nested loops: first 'for row in matrix' (outer), then 'for x in row' (inner). Option B is backwards - row isn't defined yet.

  • Order rule: the fors appear in the same order as in the loop version.

Q20. hard

Which correctly builds a 3x3 grid of zeros where rows are INDEPENDENT?

bad = [[0] * 3] * 3
bad[0][0] = 9
print(bad)    # [[9,0,0],[9,0,0],[9,0,0]] !!

good = [[0] * 3 for _ in range(3)]
good[0][0] = 9
print(good)   # [[9,0,0],[0,0,0],[0,0,0]]
  1. A grid = [[0] * 3 for _ in range(3)]
  2. B grid = [[0] * 3] * 3
  3. C Both A and B are identical
  4. D grid = [0] * 9

Answer: A — grid = [[0] * 3 for _ in range(3)]

Option B repeats a reference to the SAME row three times - changing grid[0][0] would change all three rows! The comprehension creates a fresh list each iteration, so rows are independent.

  • A classic trap when building 2D grids for games or matrices.

Q22. hard

In Python 3, does the loop variable of a comprehension LEAK outside? [x for x in range(3)] print(x)

[x for x in range(3)]
# print(x)   # NameError in Python 3
  1. A Yes - x is 2 afterwards
  2. B No - NameError: comprehensions have their own scope in Python 3
  3. C x becomes the whole list
  4. D x is always 0

Answer: B — No - NameError: comprehensions have their own scope in Python 3

In Python 3, comprehension variables live in their own hidden scope and vanish afterwards - print(x) raises NameError (unless x existed before). In Python 2 they leaked; this was fixed.

Q24. hard

Which is equivalent to map(str.upper, words)?

words = ["hi", "bye"]

map(function, iterable) applies the function to each item - exactly what [w.upper() for w in words] does. Most Python style guides prefer the comprehension for readability.
