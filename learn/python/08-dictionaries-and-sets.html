Easy questions (10)

Q1. easy

Which line creates a dictionary mapping names to ages?

ages = {"Ana": 21, "Ben": 25}
print(ages["Ana"])   # 21
  1. A ages = {"Ana": 21, "Ben": 25}
  2. B ages = ["Ana", 21, "Ben", 25]
  3. C ages = ("Ana": 21, "Ben": 25)
  4. D ages = dict["Ana"=21]

Answer: A — ages = {"Ana": 21, "Ben": 25}

Dictionaries use curly braces with key: value pairs. Each key maps to a value - like a real dictionary maps words to meanings.

DictionariesKey-value pairs

Q2. easy

How do you read Ana's age from ages = {"Ana": 21, "Ben": 25}?

ages = {"Ana": 21, "Ben": 25}
print(ages["Ana"])   # 21
# print(ages[0])      # KeyError!
  1. A ages[0]
  2. B ages["Ana"]
  3. C ages.Ana
  4. D ages("Ana")

Answer: B — ages["Ana"]

Dictionary values are accessed BY KEY, not by position: ages["Ana"] gives 21. There is no ages[0] - dicts aren't indexed by numbers (unless a number IS a key).

Q5. easy

How do you ADD a new pair to ages = {"Ana": 21}?

ages = {"Ana": 21}
ages["Ben"] = 25     # add
ages["Ana"] = 22     # update existing
print(ages)           # {'Ana': 22, 'Ben': 25}
  1. A ages["Ben"] = 25
  2. B ages.append("Ben", 25)
  3. C ages.add("Ben": 25)
  4. D ages + {"Ben": 25}

Answer: A — ages["Ben"] = 25

Assigning to a NEW key simply creates it: ages["Ben"] = 25. Assigning to an EXISTING key overwrites its value. Dicts have no append().

Q6. easy

What does "Ana" in ages check, for a dictionary ages?

ages = {"Ana": 21}
print("Ana" in ages)           # True (key)
print(21 in ages)               # False!
print(21 in ages.values())      # True
  1. A Whether "Ana" is one of the KEYS
  2. B Whether "Ana" is one of the VALUES
  3. C Whether "Ana" is a key OR a value
  4. D Nothing - in doesn't work on dicts

Answer: A — Whether "Ana" is one of the KEYS

The in operator on a dict tests KEYS only. To search values, use: 21 in ages.values().

How do you loop over BOTH keys and values at once?

ages = {"Ana": 21, "Ben": 25}

.items() yields (key, value) tuples which unpack straight into two loop variables - the standard dict-looping pattern.

Q19. easy

Which line creates a SET of three numbers?

s = {1, 2, 3}
print(type(s))   # <class 'set'>
  1. A s = {1, 2, 3}
  2. B s = [1, 2, 3]
  3. C s = (1, 2, 3)
  4. D s = set[1, 2, 3]

Answer: A — s = {1, 2, 3}

Curly braces WITHOUT colons create a set - an unordered collection of UNIQUE values. (With colons it would be a dict.)

Sets

Q21. easy

What is the output of: print({1, 2, 2, 3, 3, 3})

print({1, 2, 2, 3, 3, 3})   # {1, 2, 3}
  1. A {1, 2, 2, 3, 3, 3}
  2. B {1, 2, 3}
  3. C [1, 2, 3]
  4. D Error

Answer: B — {1, 2, 3}

Sets store each value only ONCE - duplicates are silently discarded: {1, 2, 3}. This is the defining property of a set.

Uniqueness

Q24. easy

Which method adds one element to a set?

s = {1, 2}
s.add(3)
s.add(2)     # already there - ignored
print(s)      # {1, 2, 3}
  1. A append()
  2. B add()
  3. C insert()
  4. D push()

Answer: B — add()

Sets use .add() (append and insert are list methods). Adding an element that already exists does nothing - no error, no duplicate.

add()Uniqueness

Q29. easy

Which structure best stores each student's marks BY NAME?

  1. A A dict: {"Ana": 92, "Ben": 85}
  2. B A list: [92, 85]
  3. C A set: {92, 85}
  4. D A string: "Ana 92 Ben 85"

Answer: A — A dict: {"Ana": 92, "Ben": 85}

When data is naturally 'look up X by Y', a dict is the right tool - marks by name, prices by product, settings by option. Lists are for ordered sequences, sets for uniqueness.

Q3. medium

What happens with: ages = {"Ana": 21} print(ages["Zoe"])

ages = {"Ana": 21}
print(ages.get("Zoe"))        # None
print(ages.get("Zoe", 0))     # 0 (custom default)

  2. B Prints 0
  3. C KeyError: 'Zoe'
  4. D Adds Zoe automatically

Reading a key that doesn't exist raises KeyError. Use .get() when a missing key is possible - it returns None (or your chosen default) instead of crashing.

Q7. medium

What do keys(), values() and items() return for {"a": 1, "b": 2}?

d = {"a": 1, "b": 2}
print(list(d.keys()))    # ['a', 'b']
print(list(d.values()))  # [1, 2]
print(list(d.items()))   # [('a', 1), ('b', 2)]
  1. A keys: a,b - values: 1,2 - items: pairs ('a',1),('b',2)
  2. B All three return the same thing
  3. C keys: 1,2 - values: a,b - items: nothing
  4. D They return strings

Answer: A — keys: a,b - values: 1,2 - items: pairs ('a',1),('b',2)

Three views of a dict: .keys() gives the keys, .values() the values, .items() gives (key, value) tuples - the one you loop over when you need both.

Q11. medium

Which of these CANNOT be a dictionary key?

ok = {(1, 2): "point"}      # tuple key - fine
# bad = {[1, 2]: "point"}     # TypeError: unhashable type: 'list'
  1. A "name" (a string)
  2. B 42 (an int)
  3. C (1, 2) (a tuple)
  4. D [1, 2] (a list)

Answer: D — [1, 2] (a list)

Keys must be hashable, which in practice means immutable: strings, numbers and tuples are fine; lists, dicts and sets are NOT (they can change, so their hash could change).

Q14. medium

How do you REMOVE the key "Ana" from ages?

ages = {"Ana": 21, "Ben": 25}
age = ages.pop("Ana")   # age = 21
del ages["Ben"]
print(ages)              # {}
  1. A del ages["Ana"] or ages.pop("Ana")
  2. B ages.remove("Ana")
  3. C ages.delete("Ana")
  4. D ages - "Ana"

Answer: A — del ages["Ana"] or ages.pop("Ana")

del ages["Ana"] deletes the pair; ages.pop("Ana") deletes it AND returns the value. Dicts have no .remove() method (that's for lists and sets).

Q16. medium

In Python 3.7+, in what order does a dict keep its keys?

d = {"b": 1, "a": 2}
print(list(d))          # ['b', 'a'] - insertion order
print(sorted(d))        # ['a', 'b'] - sorted view
  1. A Alphabetical order
  2. B Insertion order - the order you added them
  3. C Random order each run
  4. D Sorted by value

Answer: B — Insertion order - the order you added them

Since 3.7, dicts officially preserve insertion order - looping shows keys in the order they were added. They are never auto-sorted; use sorted(d) for that.

d = {"a": 1}

Q22. medium

What is the classic one-liner to remove duplicates from a list?

nums = [3, 1, 3, 2, 1]
print(list(set(nums)))           # e.g. [1, 2, 3]
print(list(dict.fromkeys(nums))) # [3, 1, 2] - keeps order

Convert to a set (duplicates vanish), then back to a list. Note: original order may be lost - use list(dict.fromkeys(nums)) to keep order.

Answer: B — TypeError - sets are unordered and don't support indexing

Q28. medium

Why is 'x in my_set' much faster than 'x in my_list' for large data?

big = set(range(1_000_000))
print(999_999 in big)   # instant, even for huge sets
  1. A It isn't - both are the same speed
  2. B Sets use hashing - membership is found instantly instead of checking items one by one
  3. C Sets are stored in the CPU cache
  4. D Lists compress their data

Answer: B — Sets use hashing - membership is found instantly instead of checking items one by one

A list checks every element until it finds a match (linear time). A set jumps straight to where the value would live using its hash (constant time). With a million items, that's the difference between 1 check and 500,000.

Q15. hard

Complete the word-counting pattern: counts = {} for word in words: counts[word] = ______

words = ["a", "b", "a"]
counts = {}
for w in words:
    counts[w] = counts.get(w, 0) + 1
print(counts)   # {'a': 2, 'b': 1}
  1. A counts.get(word, 0) + 1
  2. B counts[word] + 1
  3. C 1
  4. D word + 1

Answer: A — counts.get(word, 0) + 1

get(word, 0) returns the current count or 0 for a new word, then +1. Option B crashes with KeyError on the first occurrence; option C never counts past 1.

  • collections.Counter(words) does this in one line.

Q17. hard

Which merges two dicts d1 and d2 into a new dict (Python 3.9+)?

a = {"x": 1, "y": 2}
b = {"y": 99, "z": 3}
print(a | b)    # {'x': 1, 'y': 99, 'z': 3}
print({**a, **b})  # same, works in older Pythons
  1. A d1 | d2
  2. B d1 + d2
  3. C d1 & d2
  4. D merge(d1, d2)

Answer: A — d1 | d2

The | operator merges dicts (3.9+); on duplicate keys, the RIGHT side wins. d1 + d2 is a TypeError. Older code uses {**d1, **d2} or d1.update(d2).
