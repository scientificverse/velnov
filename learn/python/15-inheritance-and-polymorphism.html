Easy questions (7)

Q1. easy

What is inheritance in OOP?

class Animal:
    def eat(self):
        print("eating")

class Dog(Animal):     # Dog inherits eat()
    pass

Dog().eat()             # eating
  1. A A class (child) automatically gets the attributes and methods of another class (parent)
  2. B Copying code between files
  3. C Objects sharing memory
  4. D Importing modules

Answer: A — A class (child) automatically gets the attributes and methods of another class (parent)

Inheritance lets you build a specialized class on top of a general one: Dog inherits everything Animal has, then adds or changes what it needs. Write the common code once.

Which syntax makes Dog inherit from Animal?

Q3. easy

class Cat(Animal): pass - and Animal has a sleep() method. What does Cat().sleep() do?

class Animal:

class Cat(Animal):

Cat().sleep()   # zzz
  1. A Works - Cat inherited sleep() from Animal
  2. B AttributeError - Cat is empty

Answer: A — Works - Cat inherited sleep() from Animal

An empty child still owns everything the parent defined. Python looks for sleep on Cat, doesn't find it, and walks UP to Animal - found, called.

Q7. easy

dog = Dog() where Dog inherits Animal. What is isinstance(dog, Animal)?

Answer: A — True - an instance of a subclass IS an instance of the parent too

isinstance() respects inheritance: every Dog IS an Animal (the 'is-a' relationship). That's why isinstance is preferred over type() == for checks.

Answer: A — Yes - children extend parents freely (e.g. Dog adds fetch())

Q4. medium

Class Dog inherits from Animal. Both define speak(). What runs for Dog().speak()?

class Animal:
    def speak(self):
        return "..."

class Dog(Animal):
    def speak(self):
        return "Woof!"

print(Dog().speak())   # Woof!
  1. A Animal.speak() - parents win
  2. B Dog.speak() - the child's version OVERRIDES the parent's
  3. C Both run automatically
  4. D TypeError - ambiguous

Answer: B — Dog.speak() - the child's version OVERRIDES the parent's

Method overriding: Python checks the instance's own class FIRST. Dog.speak() shadows Animal.speak(). The parent's version still exists - reachable via super().speak().

Q5. medium

What does super() give you inside a child class?

class Animal:
    def __init__(self, name):
        self.name = name

class Dog(Animal):
    def __init__(self, name, breed):
        super().__init__(name)   # parent sets name
        self.breed = breed        # child adds breed
  1. A Access to the PARENT class's methods - e.g. super().__init__(...)
  2. B A more powerful version of self
  3. C The grandchild class
  4. D Administrator rights

Answer: A — Access to the PARENT class's methods - e.g. super().__init__(...)

super() reaches the next class up the chain - most commonly used to run the parent's __init__ so its setup isn't lost when the child overrides it.

Q8. medium

What does issubclass(Dog, Animal) check?

print(issubclass(Dog, Animal))    # True
print(issubclass(bool, int))       # True - fun fact!
  1. A Whether the Dog CLASS inherits from Animal - True here
  2. B Whether dog objects exist
  3. C Whether Animal inherits from Dog
  4. D Nothing - not a real function

Answer: A — Whether the Dog CLASS inherits from Animal - True here

issubclass compares CLASSES (isinstance compares an object to a class). issubclass(Dog, Animal) is True; issubclass(Animal, Dog) is False.

Q9. medium

What is polymorphism?

for animal in [Dog(), Cat(), Cow()]:
    print(animal.speak())   # Woof! Meow! Moo!
# one loop, three behaviors
  1. A Different classes responding to the SAME method call in their own way
  2. B One class with many names
  3. C Multiple inheritance
  4. D Converting types

Answer: A — Different classes responding to the SAME method call in their own way

Poly = many, morph = forms. Call speak() on any animal - each class provides its own version, and the calling code doesn't care which: the same line of code works for every type.

Which real-world pairs fit INHERITANCE ('is-a') best?

Q15. medium

What is the ultimate ancestor of EVERY Python class?

print(issubclass(int, object))   # True
  1. A object
  2. B type

Answer: A — object

All classes inherit from object (explicitly or not) - it provides the defaults: __init__, __str__, __eq__ and more. 'class Dog:' and 'class Dog(object):' are identical in Python 3.

Q16. medium

Is multiple inheritance allowed? class FlyingCar(Car, Airplane):

class FlyingCar(Car, Airplane):

# lookup order: FlyingCar -> Car -> Airplane -> object
  1. A Yes - a class may inherit from several parents (listed in order)
  2. B No - Python allows only one parent
  3. C Only with a plugin
  4. D Only for built-in types

Answer: A — Yes - a class may inherit from several parents (listed in order)

Python supports multiple inheritance: FlyingCar gets methods from BOTH parents. When both define the same method, the Method Resolution Order decides (left-to-right: Car wins here).

Q18. medium

In what ORDER does Python search for a method you call on an object?

  1. A The object's class first, then its parent, then grandparent... up to object
  2. B object first, then down
  3. C Random order
  4. D Alphabetical by class name

Answer: A — The object's class first, then its parent, then grandparent... up to object

Lookup climbs the inheritance chain from most-specific to most-general, stopping at the FIRST match - which is exactly why child methods override parent ones.

What does method overriding let a subclass do?

class Animal:
    def speak(self):
        return "some sound"

class Cat(Animal):
    def speak(self):        # overrides
        return "Meow"

print(Cat().speak())        # Meow
print(Animal().speak())     # some sound
  1. A Provide its OWN version of a method the parent already defined, replacing it for instances of the subclass
  2. B Delete the parent's method everywhere
  3. C Rename the parent method
  4. D Call two methods at once

Overriding = redefining an inherited method in the child with the same name. The child's version is used for child instances; the parent (and other subclasses) keep the original. Combine with super() to extend rather than fully replace.

What breaks here? class Animal: def __init__(self, name): self.name = name class Dog(Animal): def __init__(self, breed): self.breed = breed d = Dog("lab") print(d.name)

class Dog(Animal):
    def __init__(self, name, breed):

What is DUCK TYPING?

class Robot:            # no Animal parent!
    def speak(self):
        return "beep"

for thing in [Dog(), Robot()]:
    print(thing.speak())   # works - both can speak
  1. A 'If it walks like a duck and quacks like a duck...' - Python cares about what an object CAN DO, not what class it is
  2. B A special duck class in the standard library

Q14. hard

What is COMPOSITION, and when is it better than inheritance?

class Engine:
    def start(self): print("vroom")

class Car:
    def __init__(self):
        self.engine = Engine()   # has-a
    def start(self):
        self.engine.start()
  1. A Storing other objects as attributes ('has-a') - better when the relationship isn't truly 'is-a'
  2. B Combining two classes into one file
  3. C A stricter form of inheritance
  4. D Composing music with Python

Answer: A — Storing other objects as attributes ('has-a') - better when the relationship isn't truly 'is-a'

A Car HAS an Engine, so Engine is an attribute - not a parent. Composition is flexible (swap engines at runtime, no fragile hierarchies). Modern advice: 'prefer composition over inheritance' unless the is-a test clearly passes.

Q17. hard

class C(A, B) - both A and B define hello(). Which runs for C().hello()?

class A:
    def hello(self): return "A"
class B:
    def hello(self): return "B"
class C(A, B): pass

print(C().hello())   # A
print(C.__mro__)      # (C, A, B, object)
  1. A A's - the MRO checks parents LEFT to RIGHT as listed
  2. B B's - rightmost wins
  3. C Both run
  4. D TypeError - conflict

Answer: A — A's - the MRO checks parents LEFT to RIGHT as listed

The Method Resolution Order for C(A, B) is C -> A -> B -> object. First match wins: A.hello(). Inspect any class's order with C.__mro__ or C.mro().

Q20. hard

How do you make a 'template' method that children MUST implement?

class Shape:
    def area(self):
        raise NotImplementedError("subclass must define area")

class Circle(Shape):
    def area(self):
        return 3.14159 * self.r ** 2
  1. A Raise NotImplementedError in the parent (or use the abc module's @abstractmethod)
  2. B Leave the method out entirely
  3. C Name it _must_implement
  4. D Python can't express this

Answer: A — Raise NotImplementedError in the parent (or use the abc module's @abstractmethod)

The simple way: the parent's method raises NotImplementedError, so forgetting to override it fails loudly. The formal way: inherit from abc.ABC and mark methods @abstractmethod - then instantiating an incomplete child is impossible.

Q25. hard

Why is 'type(x) == Dog' usually WORSE than 'isinstance(x, Dog)'?

class Puppy(Dog): pass
p = Puppy()
print(type(p) == Dog)        # False!
print(isinstance(p, Dog))    # True
  1. A type() ignores inheritance - a Puppy(Dog) instance would FAIL the type check but pass isinstance
  2. B type() is slower
  3. C type() doesn't exist
  4. D They're always identical

Answer: A — type() ignores inheritance - a Puppy(Dog) instance would FAIL the type check but pass isinstance

Exact-type checks break polymorphism: code demanding type(x) == Dog rejects perfectly good subclasses. isinstance accepts the whole family - almost always what you want.

Q28. hard

What is the 'diamond problem', and how does Python cope?

class A: pass
class B(A): pass
class C(A): pass
class D(B, C): pass
print(D.__mro__)   # D, B, C, A, object
  1. A D inherits from B and C which both inherit A - Python's MRO (C3 linearization) gives ONE consistent lookup order, each class visited once
  2. B A crash when classes form a square
  3. C Python forbids the diamond shape entirely
  4. D Methods run twice

Answer: A — D inherits from B and C which both inherit A - Python's MRO (C3 linearization) gives ONE consistent lookup order, each class visited once

The diamond: D(B, C), B(A), C(A). Which A-method does D see, and does A run twice? Python's C3 algorithm computes a deterministic order (D, B, C, A) and super() follows it - so cooperative calls visit each class exactly once.
