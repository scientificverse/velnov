Iterators and Generators – values one at a time

In this overview: Iterables and iterators · Generator functions and yield · Why generators save memory · Generators are one-pass · Generator expressions and pipelines · yield from · Writing an iterator class · Lazy built-ins and itertools · Common misconceptions · Quick revision · Test your understanding

1. Iterables and iterators

  • An iterable can be looped over: lists, strings, dicts, ranges.
  • An iterator is the object that hands out the values one at a time with next(). iter(x) gets one from an iterable.
  • When an iterator runs out, next() raises StopIteration.
nums = [1, 2]
it = iter(nums)
print(next(it))
print(next(it))
print(next(it, "done"))   # a default instead of StopIteration
Output1
2
done

Remember: A for loop calls iter() once, then next() again and again, and stops quietly at StopIteration.

2. Generator functions and yield

A function that contains yield is a generator function. Calling it runs nothing: it returns a generator object. Each next() runs the body up to the next yield, pauses there, and remembers everything.

def count_up(n):
    for i in range(1, n + 1):
        yield i

g = count_up(3)
print(next(g))
print(list(g))          # the rest
Output1
[2, 3]

Pause and resume

def demo():
    print("start")
    yield 1
    print("resumed")
    yield 2

g = demo()
print("before")
print(next(g))
print(next(g))
Outputbefore
start
1
resumed
2

3. Why generators save memory

A list stores every value at once. A generator produces each value only when asked, so it can handle huge or even endless data in very little memory.

from itertools import islice

def naturals():
    n = 1
    while True:          # endless, but harmless
        yield n
        n += 1

print(list(islice(naturals(), 5)))

def fib():
    a, b = 0, 1
    while True:
        yield a
        a, b = b, a + b

print(list(islice(fib(), 8)))
Output[1, 2, 3, 4, 5]
[0, 1, 1, 2, 3, 5, 8, 13]

4. Generators are one-pass

Once a generator is used up, it stays empty. Call the generator function again for a fresh one, or save the values in a list if you need two passes.

def gen():
    yield 1
    yield 2

g = gen()
print(list(g))
print(list(g))
print(list(gen()))      # a new generator
Output[1, 2]
[]
[1, 2]

Remember: Even x in g uses up values from a generator.

5. Generator expressions and pipelines

(expr for x in items) is a one-line generator. Chaining them makes a pipeline: each item flows through every step one at a time.

lines = ["ok", "ERROR disk", "ok", "ERROR net"]
errors = (l for l in lines if "ERROR" in l)
short = (l.split()[1] for l in errors)
print(list(short))
print(sum(x * x for x in range(4)))
Output['disk', 'net']
14

6. yield from

yield from iterable hands out every value of another iterable. It is very useful in recursive generators.

def all_items():
    yield from [1, 2]
    yield from "ab"

print(list(all_items()))
Output[1, 2, 'a', 'b']

7. Writing an iterator class

A class becomes an iterator by defining __iter__ (which returns self) and __next__ (which returns the next value, or raises StopIteration). Generators do all of this for you, which is why they are usually preferred.

class Countdown:
    def __init__(self, n):
        self.n = n
    def __iter__(self):
        return self
    def __next__(self):
        if self.n <= 0:
            raise StopIteration
        self.n -= 1
        return self.n + 1

print(list(Countdown(3)))
Output[3, 2, 1]

8. Lazy built-ins and itertools

range, map, filter and zip are lazy too. The itertools module has ready-made iterator tools: count, cycle, chain and islice.

from itertools import chain, count, islice
m = map(str.upper, ["a", "b"])
print(m.__class__.__name__, list(m))
print(list(chain([1, 2], [3])))
print(list(islice(count(10), 3)))
print(10**11 in range(10**12))    # instant: computed, not searched
Outputmap ['A', 'B']
[1, 2, 3]
[10, 11, 12]
True

You can loop over a generator twice.Generators are one-pass; after use they are empty.
yield works like return.return ends the function; yield pauses it and resumes later.
g[0] gives a generator's first value.Generators can't be indexed; use next(g).

nums = [1, 2, 3]        # iterable

Q5. medium

What is the KEY difference between yield and return?

def demo():
    print("start")
    yield 1
    print("resumed")
    yield 2

g = demo()
next(g)   # prints start, gives 1
next(g)   # prints resumed, gives 2
  1. A return exits for good; yield PAUSES the function, remembers everything, and resumes on the next next()
  2. B yield is just a faster return
  3. C return sends multiple values
  4. D No difference

Answer: A — return exits for good; yield PAUSES the function, remembers everything, and resumes on the next next()

yield hands out a value and freezes the function mid-flight - locals, loop position, everything preserved. The next next() resumes right after the yield. return (or falling off the end) raises StopIteration.

Q10. medium

Which two methods must a CLASS implement to be its own iterator?

class Countdown:
    def __init__(self, n):
        self.n = n
    def __iter__(self):
        return self
    def __next__(self):
        if self.n <= 0:
            raise StopIteration
        self.n -= 1
        return self.n + 1

print(list(Countdown(3)))   # [3, 2, 1]
  1. A __iter__ (returns self) and __next__ (returns the next value or raises StopIteration)
  2. B __loop__ and __stop__
  3. C __for__ and __in__
  4. D next() and prev()

Answer: A — __iter__ (returns self) and __next__ (returns the next value or raises StopIteration)

The iterator protocol: __iter__ makes the object usable in for loops; __next__ supplies each value and raises StopIteration when done. Generators implement all this automatically - which is why they're usually preferred.

Q30. medium
