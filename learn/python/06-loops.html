Easy questions (12)

Q1. easy

How many times does this loop run? for i in range(5): print(i)

for i in range(5):
    print(i)   # 0 1 2 3 4
  1. A 4
  2. B 5
  3. C 6
  4. D Infinite

Answer: B — 5

range(5) generates 0, 1, 2, 3, 4 - five values, so the body runs 5 times. The stop value (5) is never included.

range()Iteration

Q2. easy

What values does range(2, 10, 2) produce?

print(list(range(2, 10, 2)))   # [2, 4, 6, 8]
print(list(range(1, 6)))        # [1, 2, 3, 4, 5]
  1. A 2, 4, 6, 8, 10
  2. B 2, 4, 6, 8
  3. C 4, 6, 8, 10
  4. D 2, 10, 2

Answer: B — 2, 4, 6, 8

range(start, stop, step): begin at 2, jump by 2, stop BEFORE 10 - giving 2, 4, 6, 8. The stop value is always excluded.

range()Step

Q3. easy

What does the break statement do inside a loop?

break terminates the loop at once - execution jumps to the first line AFTER the loop. Used to stop early when you've found what you need.

Q5. easy

Which is the correct while loop that counts 1 to 3?

i = 1
while i <= 3:
    print(i)
    i += 1     # without this: infinite loop!
  1. A i = 1\nwhile i <= 3:\n print(i)\n i += 1
  2. B while i <= 3:\n print(i)
  3. C while (i = 1; i <= 3; i++):\n print(i)
  4. D while i in range(3): print(i)

Answer: A — i = 1\nwhile i <= 3:\n print(i)\n i += 1

A while loop needs: the variable created BEFORE the loop, a condition, and an update INSIDE the loop. Option B never defines or updates i; option C is C-language syntax.

Q6. easy

What causes an INFINITE loop most often?

i = 0

    print(i)
    # forgot i += 1  -> prints 0 forever!
  1. A Using range() with big numbers
  2. B Forgetting to update the loop variable inside a while loop
  3. C Using break
  4. D Nesting loops

Answer: B — Forgetting to update the loop variable inside a while loop

If the while condition never becomes False - typically because you forgot i += 1 - the loop runs forever. Press Ctrl+C to stop a runaway program.

Q23. easy

Q4. medium

What does the continue statement do inside a loop?

for i in range(5):
    if i == 2:
        continue   # skip printing 2
    print(i)       # 0 1 3 4
  1. A Exits the loop entirely
  2. B Skips the rest of the current iteration and moves to the next one
  3. C Restarts the loop from the beginning
  4. D Does nothing

Answer: B — Skips the rest of the current iteration and moves to the next one

continue jumps straight to the next iteration, skipping any remaining statements in the loop body this time around. break, by contrast, exits the loop completely.

Q10. medium

What does enumerate() give you in: for i, fruit in enumerate(["apple", "mango"]):

Q11. medium

Which range counts DOWN from 10 to 1?

for i in range(10, 0, -1):

  1. A range(10, 0, -1)
  2. B range(10, 1)
  3. C range(1, 10, -1)

Answer: A — range(10, 0, -1)

A negative step walks backwards: range(10, 0, -1) gives 10, 9, 8, ... 1 (stop 0 excluded). Option C produces nothing - you can't go from 1 down to 10.

Q15. medium

In a NESTED loop, what does break exit?

for i in range(3):
    for j in range(3):
        if j == 1:
            break      # exits inner only
    print(i)            # still prints 0 1 2
  1. A All loops at once
  2. B Only the innermost loop containing it
  3. C The outermost loop
  4. D The whole program

Answer: B — Only the innermost loop containing it

break only exits the single loop it lives in - the outer loop continues. To exit multiple levels, use a flag variable, return from a function, or restructure the code.

Python has NO do-while loop. The idiom is while True: with a break when the exit condition is met - the body always runs at least once.

Q19. medium

What is the difference between continue and pass?

    print(i)        # 0 2  (1 skipped)

        pass

  1. A They are identical
  2. B continue skips to the next iteration; pass does nothing and execution continues to the next line

Answer: B — continue skips to the next iteration; pass does nothing and execution continues to the next line

continue actively jumps to the next iteration - lines after it don't run. pass is a no-op placeholder - lines after it DO run normally.

Q25. medium

Which is the more Pythonic way to loop over a list's values?

for item in items:            # best
for i, item in enumerate(items):  # need index too
for i in range(len(items)):    # only to assign items[i] = ...

Q14. hard

What is the loop-else clause? for n in nums: if n == target: break else: print("not found")

for n in [1, 3, 5]:
    if n == 4:
        print("found")
        break
else:
    print("not found")   # runs - no break happened
  1. A It runs after every iteration
  2. B It runs only when the loop finished WITHOUT hitting break
  3. C It's a syntax error - else can't follow for
  4. D It runs only when break happened

Answer: B — It runs only when the loop finished WITHOUT hitting break

Python's unusual for-else: the else block runs when the loop completes normally (no break). Perfect for search loops - if break never fired, the item wasn't found.

  • Think of else here as 'no-break'.

Q21. hard

What does zip() do in: for name, mark in zip(["Ana", "Ben"], [90, 85]):

names = ["Ana", "Ben"]
marks = [90, 85]
for name, mark in zip(names, marks):
    print(name, mark)
# Ana 90
# Ben 85
  1. A Compresses the lists to save memory

zip() walks multiple sequences in parallel, yielding tuples of matching positions. It stops at the SHORTEST sequence.

Q22. hard

What is the output? for i in range(3): i = 100 print(i)

for i in range(3):
    i = 100      # overwritten next iteration
    print(i)      # 100 100 100
print(i)          # 100 (last value assigned)
  1. A 100
  2. B 2
  3. C 102
  4. D Error

Answer: A — 100

Tricky! Reassigning i inside the body doesn't affect the iteration - each pass, the for loop reassigns i to the NEXT range value. After the final pass, i was set to 100 by the body, so print shows 100.

  • The loop still runs exactly 3 times - you can't skip ahead by changing i.

Q28. hard

Why is modifying a list WHILE looping over it dangerous? for x in nums: if x < 0: nums.remove(x)

nums = [1, -2, -3, 4]
for x in nums[:]:        # loop over a copy
    if x < 0:
        nums.remove(x)

# or better:
nums = [x for x in nums if x >= 0]
  1. A It's perfectly safe
  2. B Removing items shifts positions, so the loop SKIPS elements
  3. C It raises SyntaxError
  4. D The list becomes immutable during loops

Answer: B — Removing items shifts positions, so the loop SKIPS elements

When you remove an item, everything after it shifts left - but the loop's internal position still advances, silently skipping the next element. Loop over a COPY (nums[:]) or build a new filtered list instead.

  • A very common source of 'why did it skip one?' bugs.

List mutationCopies
