Q2. easy

What happens if you define a function but never CALL it?

def greet():

greet()            # NOW it prints
  1. A Its body runs once automatically
  2. B Nothing - the body only runs when the function is called
  3. C SyntaxError
  4. D It runs at the end of the program

Answer: B — Nothing - the body only runs when the function is called

def only CREATES the function. The body executes each time you call it with parentheses: greet(). Defining without calling produces no output.

Q3. easy

What does a function return if it has no return statement?

  1. A 0
  2. B Empty string
  3. C None
  4. D Error

Q4. easy

What is the difference between print() and return in a function?

def add(a, b):
    return a + b

total = add(2, 3) * 10   # 50 - reusable!
  1. A None - they do the same
  2. B print shows a value on screen; return sends the value back to the caller for further use
  3. C return shows on screen; print sends back
  4. D return only works with numbers

Answer: B — print shows a value on screen; return sends the value back to the caller for further use

print() is for humans (display only); return is for code - the caller receives the value and can store, compare or reuse it. A function that only prints can't have its result used in calculations.

Q5. easy

In def greet(name): ... and the call greet("Ana") - what are name and "Ana" called?

  1. A name is the parameter; "Ana" is the argument
  2. B name is the argument; "Ana" is the parameter
  3. C Both are parameters
  4. D Both are arguments

Answer: A — name is the parameter; "Ana" is the argument

PARAMETER = the placeholder in the definition (name). ARGUMENT = the actual value passed when calling ("Ana"). Parameter is the parking spot, argument is the car.

Q18. easy

What does return do the moment it executes?

def check(n):
    if n < 0:
        return "negative"   # exits here for negatives
    return "positive"
    print("never runs")
  1. A Pauses the function
  2. B Immediately EXITS the function, handing back the value - remaining lines don't run
  3. C Prints the value
  4. D Restarts the function

Answer: B — Immediately EXITS the function, handing back the value - remaining lines don't run

return ends the function on the spot. Code after an executed return is unreachable. Multiple returns are fine - typically one per branch.

Q25. easy

By PEP 8 convention, function names should be written as:

  1. A snake_case: calculate_total()
  2. B CamelCase: CalculateTotal()
  3. C ALLCAPS: CALCULATETOTAL()
  4. D kebab-case: calculate-total()

Answer: A — snake_case: calculate_total()

Functions and variables use snake_case; CamelCase is reserved for class names; ALL_CAPS for constants. (kebab-case is illegal - hyphens mean subtraction.)

PEP 8Naming conventions

Q30. easy

Why split a program into functions at all?

  1. A Reuse, readability, easier testing, and no copy-pasted code
  2. B Functions make programs run faster automatically
  3. C Python requires at least 5 functions
  4. D Only to use return

Answer: A — Reuse, readability, easier testing, and no copy-pasted code

Functions package logic behind a name: write once, call anywhere, test in isolation, and read programs as a story of well-named steps. The DRY principle: Don't Repeat Yourself.

Q9. medium

What is *args used for in a function definition?

def total(*args):
    return sum(args)

print(total(1, 2, 3))   # 6
print(total(5))          # 5
  1. A To accept any number of positional arguments as a tuple
  2. B To multiply arguments
  3. C To pass arguments by reference
  4. D To accept keyword arguments as a dict

Answer: A — To accept any number of positional arguments as a tuple

*args collects extra positional arguments into a tuple, so the function accepts any count: total(1), total(1,2,3)... **kwargs does the same for keyword arguments (into a dict).

Q14. medium

What happens? def f(): x = 10 f() print(x)

def f():

  1. A Prints 10
  2. B NameError - x is local to f and doesn't exist outside
  3. C Prints None

Answer: B — NameError - x is local to f and doesn't exist outside

Variables created inside a function are LOCAL - they exist only while the function runs and vanish afterwards. To get the value out, return it.

Q15. medium

Q21. medium

What is recursion?

def factorial(n):
    if n == 0:          # base case
        return 1
    return n * factorial(n - 1)

print(factorial(5))   # 120
  1. A A function that calls ITSELF, with a base case to stop
  2. B A loop inside a function
  3. C Calling two functions at once
  4. D A function without a return

Answer: A — A function that calls ITSELF, with a base case to stop

A recursive function solves a problem by calling itself on a smaller piece, stopping at a base case. Classic example: factorial(n) = n * factorial(n-1), stopping at factorial(0) = 1.

RecursionBase case

Q23. medium

Q29. medium

What is the output? def outer(): def inner(): return "hi" return inner() print(outer())

def outer():
    def inner():
        return "hi"
    return inner()   # calls inner, returns 'hi'

print(outer())        # hi
  1. A hi
  2. B inner
  3. C Error - functions can't nest
  4. D None

Answer: A — hi

Functions can be defined INSIDE other functions. outer defines inner, calls it (note the parentheses in 'return inner()'), and returns its result: 'hi'. Returning inner WITHOUT parentheses would return the function itself - that's how closures work (next topics!).

Q8. hard

Which call is INVALID for def f(a, b)?

f(1, 2)       # ok - all positional
f(1, b=2)     # ok - positional then keyword
# f(a=1, 2)   # SyntaxError!
  1. A f(1, 2)
  2. B f(a=1, b=2)
  3. C f(1, b=2)
  4. D f(a=1, 2)

Answer: D — f(a=1, 2)

Positional arguments must come BEFORE keyword arguments. f(a=1, 2) puts a positional after a keyword - SyntaxError: positional argument follows keyword argument.

Q16. hard

Why does this raise UnboundLocalError? count = 0 def inc(): count = count + 1 inc()

count = 0
def inc():
    global count
    count += 1     # now legal

# better style:
def inc(count):
    return count + 1
  1. A count doesn't exist at all
  2. B The assignment makes count LOCAL for the whole function, so 'count + 1' reads a local that has no value yet
  3. C Functions can't use numbers
  4. D inc needs a parameter

Answer: B — The assignment makes count LOCAL for the whole function, so 'count + 1' reads a local that has no value yet

Because the function ASSIGNS to count, Python treats count as local everywhere in the function - including the right-hand side, where it hasn't been given a value yet. Fix: declare 'global count', or better, pass it in and return the new value.

UnboundLocalErrorglobalScope

Q17. hard

THE classic Python trap - what is the output? def add(item, lst=[]): lst.append(item) return lst print(add(1)) print(add(2))

def add(item, lst=None):
    if lst is None:
        lst = []       # fresh list per call
    lst.append(item)
    return lst
  1. A [1] then [2]
  2. B [1] then [1, 2] - the SAME default list is reused between calls
  3. C [1, 2] then [1, 2]
  4. D Error

Answer: B — [1] then [1, 2] - the SAME default list is reused between calls

Default values are created ONCE, at function definition - not per call. Every call without lst shares the same list, which keeps growing. Fix: default to None and create the list inside.

  • Asked in countless interviews - the 'mutable default argument' trap.

Q20. hard

Which definition is INVALID?

def f(a, b=2):     # correct order
# def f(a=1, b):   # SyntaxError!
  1. A def f(a, b=2):
  2. B def f(a=1, b):
  3. C def f(a, b=2, c=3):
  4. D def f(*args, **kwargs):

Answer: B — def f(a=1, b):

Parameters WITH defaults must come AFTER those without: def f(a=1, b): is a SyntaxError - Python couldn't tell which argument f(5) fills. Required first, optional after.

Q22. hard

What happens to a recursive function with NO base case?

def broken(n):
    return broken(n - 1)   # no base case!
# broken(5)   # RecursionError
  1. A It runs forever silently
  2. B RecursionError: maximum recursion depth exceeded
  3. C It returns None
  4. D SyntaxError at definition

Answer: B — RecursionError: maximum recursion depth exceeded

Each call stacks up; without a stopping condition Python hits its recursion limit (about 1000 calls) and raises RecursionError - its protection against a true infinite recursion crash.

RecursionErrorCall stack
