Q1. easy

Which function opens a file in Python?

f = open("notes.txt", "r")
text = f.read()
f.close()
  1. A open()
  2. B file()
  3. C read()
  4. D load()

Answer: A — open()

open(path, mode) returns a file object: open("notes.txt", "r") opens for reading. The mode defaults to "r" if omitted.

open()File modes

Q2. easy

What does mode "r" mean in open("data.txt", "r")?

  1. A Read - file must already exist
  2. B Remove the file
  3. C Rename the file
  4. D Read and write

Answer: A — Read - file must already exist

"r" opens for READING only. If the file doesn't exist you get FileNotFoundError. Other modes: "w" write, "a" append, "x" create-new.

Q4. easy

Which mode ADDS to the end of a file without deleting what's there?

with open("log.txt", "a") as f:
    f.write("user logged in\n")
  1. A "w"
  2. B "a"
  3. C "r"
  4. D "end"

Answer: B — "a"

"a" = append. Writes always go to the end; existing content is safe. Perfect for log files. The file is created if it doesn't exist.

Q5. easy

What is the PREFERRED way to open files, and why?

with open("notes.txt") as f:
    text = f.read()
# file is ALREADY closed here
  1. A with open(...) as f: - the file closes automatically, even on errors
  2. B f = open(...) - simpler
  3. C It makes no difference
  4. D global open

Answer: A — with open(...) as f: - the file closes automatically, even on errors

The with statement (context manager) guarantees the file is closed when the block ends - even if an exception occurs inside. No forgotten close(), no leaked file handles.

  • Modern Python code almost never calls close() manually.

Q3. medium

What is the DANGER of mode "w"?

open("log.txt", "w")   # content GONE
open("log.txt", "a")   # content kept, writes go to the end
  1. A It's slower
  2. B It ERASES the file's existing content the moment it opens
  3. C It can't create new files
  4. D It locks the file forever

Answer: B — It ERASES the file's existing content the moment it opens

"w" truncates: opening an existing file in "w" instantly wipes it - even if you never write anything. Use "a" (append) to keep existing content and add to the end.

  • Real data has been lost to this. Double-check your mode!

Q7. medium

What is the difference between readline() and readlines()?

with open("data.csv") as f:
    header = f.readline()     # first line only
    rest = f.readlines()       # remaining lines as a list
  1. A readline() returns the NEXT single line; readlines() returns ALL lines as a list
  2. B They're identical
  3. C readlines() reads one line
  4. D readline() returns a list

Answer: A — readline() returns the NEXT single line; readlines() returns ALL lines as a list

readline() advances one line per call - good for reading just the header. readlines() loads every line into a list at once - convenient, but memory-heavy for huge files.

Q8. medium

What is the BEST way to process a large file line by line?

with open("big.log") as f:
    for line in f:
        if "ERROR" in line:
            print(line.strip())
  1. A for line in f: - iterate the file object directly
  2. B f.read().split() always
  3. C readlines() then loop
  4. D while f.next():

Answer: A — for line in f: - iterate the file object directly

A file object is iterable - looping it reads ONE line at a time, so even gigabyte files use tiny memory. readlines() would load everything at once.

Q9. medium

Why call line.strip() when reading lines from a file?

for line in f:
    name = line.strip()
    if name == "cat":    # now matches
        print("found")
  1. A Each line ends with an invisible \n newline - strip() removes it
  2. B To remove all spaces inside the line
  3. C Files require it
  4. D To convert to lowercase

Answer: A — Each line ends with an invisible \n newline - strip() removes it

Lines keep their trailing newline character, so print(line) double-spaces and comparisons fail ('cat\n' != 'cat'). strip() (or rstrip()) cleans it off.

Q11. medium

What's the catch with f.write() compared to print()?

f.write("a")
f.write("b")     # file contains: ab
f.write("c\n")   # add \n yourself
print("d", file=f)  # or use print
  1. A write() does NOT add a newline automatically - you must include \n yourself
  2. B write() adds two newlines
  3. C write() can't write strings
  4. D No difference

Answer: A — write() does NOT add a newline automatically - you must include \n yourself

print() appends \n for you; write() writes ONLY what you pass. Forgetting \n glues all your lines into one. Alternative: print("text", file=f) adds the newline.

Q15. medium

When do you need mode "rb" or "wb"?

with open("photo.jpg", "rb") as src:
    data = src.read()          # bytes
with open("copy.jpg", "wb") as dst:
    dst.write(data)
  1. A For BINARY files - images, audio, zip files - where data is bytes, not text
  2. B For very big text files
  3. C For read-backwards mode
  4. D Never - text mode handles everything

Answer: A — For BINARY files - images, audio, zip files - where data is bytes, not text

The b suffix switches to binary mode: read() returns bytes instead of str, and no newline translation happens. Copying an image in text mode corrupts it.

Q16. medium

What happens when you read from a file AFTER closing it?

A closed file object refuses all operations with ValueError. A common bug: doing f.read() OUTSIDE the with block - the file is already closed there.

Q23. medium

Why pass encoding="utf-8" to open()?

with open("notes.txt", encoding="utf-8") as f:
    text = f.read()   # handles any language
  1. A So text with any language/emoji reads and writes correctly on every OS
  2. B It compresses the file
  3. C It's required for numbers
  4. D It makes files read-only

Answer: A — So text with any language/emoji reads and writes correctly on every OS

Without it, Python uses a platform-dependent default (often cp1252 on Windows) - files with ñ, 中文 or emoji can crash or garble. Explicit utf-8 makes your code portable.

  • Good habit: always specify encoding for text files.

Q17. hard

Why does the SECOND read() return an empty string? data1 = f.read() data2 = f.read()

data1 = f.read()   # everything; cursor at end
data2 = f.read()   # '' - nothing left
f.seek(0)           # rewind
data3 = f.read()   # everything again
  1. A The file position is at the END after the first read - there's nothing left to read
  2. B Files can only be read once ever
  3. C It's a bug in Python
  4. D The file gets deleted after reading

Answer: A — The file position is at the END after the first read - there's nothing left to read

A file object keeps a position cursor. read() moves it to the end; the next read() starts there and finds nothing. f.seek(0) rewinds to the beginning to read again.

Q18. hard

What is the difference between json.dump() and json.dumps()?

import json
text = json.dumps({"a": 1})   # '{"a": 1}' - a string

Q30. hard

You need to save a Python LIST so another run of your program can reload it. Best simple approach?

import json
scores = [90, 85, 77]
with open("scores.json", "w") as f:
    json.dump(scores, f)

with open("scores.json") as f:

  1. A json.dump() it to a file, json.load() to restore
  2. B write(str(list)) and eval() it back
  3. C Print it and copy-paste later
  4. D Lists can't be saved

Answer: A — json.dump() it to a file, json.load() to restore

JSON handles lists, dicts, strings, numbers and bools - safe and readable. eval() on file content is a security hole (it executes anything). For arbitrary Python objects, the pickle module exists - but JSON is the safe default.
