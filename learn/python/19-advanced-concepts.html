What is the walrus operator := used for (Python 3.8+)?

while (line := input()) != "quit":
    print(line)

# instead of:
# line = input()

  1. A Assign a value AND use it in the same expression
  2. B Compare two values
  3. C Multiply and assign
  4. D Unpack a tuple

Answer: A — Assign a value AND use it in the same expression

The walrus operator assigns within an expression, avoiding a separate line. Common in while loops and comprehensions where you'd otherwise compute a value twice.

Q1. hard

What is the GIL (Global Interpreter Lock)?

  1. A A lock that lets only ONE thread run Python bytecode at a time in CPython
  2. B A security feature for imports
  3. C A garbage collector
  4. D A way to lock files

Answer: A — A lock that lets only ONE thread run Python bytecode at a time in CPython

In CPython, the GIL ensures only one thread executes Python bytecode at once. This means threads don't give true parallelism for CPU-bound work - but they still help I/O-bound tasks (waiting on network/disk).

  • For CPU-bound parallelism, use multiprocessing instead of threading.

ThreadingmultiprocessingCPython

Q2. hard

For CPU-heavy work needing real parallelism, which should you use?

  1. A multiprocessing - separate processes each with their own interpreter, bypassing the GIL
  2. B threading - always faster
  3. C A bigger for loop
  4. D asyncio

Answer: A — multiprocessing - separate processes each with their own interpreter, bypassing the GIL

Because the GIL blocks parallel bytecode execution, threads can't speed up CPU-bound work. multiprocessing spawns separate processes (each with its own GIL) that run on multiple cores. asyncio and threading suit I/O-bound work.

Q3. hard

What is the difference between a shallow copy and a deep copy?

import copy
a = [[1, 2], [3, 4]]
b = a.copy()          # shallow
b[0][0] = 99
print(a)               # [[99, 2], [3, 4]] - inner shared!
c = copy.deepcopy(a)   # fully independent
  1. A Shallow copies the outer object but shares nested objects; deep copies everything recursively
  2. B They are identical
  3. C Deep copy is faster
  4. D Shallow copy only works on strings

Answer: A — Shallow copies the outer object but shares nested objects; deep copies everything recursively

A shallow copy (list[:], .copy(), copy.copy) duplicates the top level but the inner objects are still shared. copy.deepcopy() recursively duplicates everything, so nested objects are independent too.

copy moduleReferences

  2. B 0 - b is fully independent
  3. C None

Normally each instance stores attributes in a __dict__. __slots__ replaces it with a fixed layout: less memory per object (big when you have millions) and no new attributes allowed.

Q18. hard

Why can small ints behave oddly with is? a = 256; b = 256; print(a is b) # True a = 257; b = 257; print(a is b) # often False

  1. A CPython caches small integers (-5 to 256), so identical small ints share one object; larger ones may not
  2. B It's a bug
  3. C 256 is special in binary
  4. D is never works on numbers

Answer: A — CPython caches small integers (-5 to 256), so identical small ints share one object; larger ones may not

CPython pre-creates and reuses int objects from -5 to 256, so 'a is b' is True for those. Beyond that range, separate objects may be created. This is exactly why you compare numbers with ==, never is.

  • An implementation detail - never rely on it in real code.

Q24. hard

What are *args and **kwargs at a CALL site (unpacking)? f(*my_list, **my_dict)

def add(a, b, c): return a + b + c
nums = [1, 2, 3]
print(add(*nums))   # 6
  1. A * spreads a list into positional arguments; ** spreads a dict into keyword arguments
  2. B They multiply the arguments
  3. C They create new lists
  4. D They are only valid in definitions

Answer: A — * spreads a list into positional arguments; ** spreads a dict into keyword arguments

At a call, * and ** unpack: f(*[1,2,3]) is f(1,2,3), and f(**{'a':1}) is f(a=1). The mirror image of collecting them with *args/**kwargs in a definition.
