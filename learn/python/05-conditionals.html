Q1. easy

Which is the correct syntax for an if statement?

x = 10
if x > 5:
    print("big")
  1. A if (x > 5) { print("big") }
  2. B if x > 5:\n print("big")
  3. C if x > 5 then print("big")
  4. D if x > 5 print("big")

Answer: B — if x > 5:\n print("big")

Python's if needs a colon at the end of the condition and an INDENTED body on the next line. No parentheses or braces are required.

  • Forgetting the colon is the #1 beginner syntax error.

Q2. easy

What does elif mean?

if score >= 90:
    print("A")
elif score >= 75:
    print("B")
elif score >= 60:
    print("C")
else:
    print("Fail")
  1. A End the if statement
  2. B 'Else if' - test another condition when the previous ones were False
  3. C A loop keyword
  4. D Error handling

Answer: B — 'Else if' - test another condition when the previous ones were False

elif is short for 'else if' - it adds another condition that is only checked when all previous if/elif conditions were False. You can chain as many as you like.

Q3. easy

When does the else block run?

Answer: B — Only when the if (and every elif) condition was False

else is the catch-all: it runs exactly when none of the if/elif conditions matched. It takes no condition of its own.

Q10. easy

What happens with: if x = 5: print("five")

if x == 5:    # correct - comparison
    print("five")
  1. A Prints five when x is 5
  2. B SyntaxError - assignment is not allowed as a condition
  3. C Always prints five
  4. D Sets x to 5 silently

Answer: B — SyntaxError - assignment is not allowed as a condition

A single = is assignment, and Python forbids it inside an if condition - you get a SyntaxError immediately. The comparison you want is == (two equals signs).

  • In C this bug compiles and runs wrong; Python catches it for you.

Q5. medium

What is the output of: x = 7 if x > 5: print("A") elif x > 6: print("B")

# Order matters in elif chains!
# Put the most specific condition first.
  1. A A
  2. B B
  3. C A then B
  4. D Nothing

Answer: A — A

In an if/elif chain, Python stops at the FIRST True condition. x > 5 is True, so 'A' prints and the elif is never even checked - even though x > 6 is also True.

  • This is the key difference between elif and separate ifs.

Q7. medium

What is the output of: items = [] if items: print("has items") else: print("empty")

if len(items) > 0:   # works, but wordier
  1. A has items
  2. B empty
  3. C []
  4. D Error

Answer: B — empty

An empty list is falsy, so 'if items:' fails and else runs. This is the Pythonic way to test for emptiness - no need for len(items) == 0.

Q8. medium

Answer: A — status = "adult" if age >= 18 else "minor"

Q12. medium

Q15. hard

Bug hunt! Why does this print 'teen' for EVERY age? if age == 13 or 14 or 15: print("teen")

# WRONG - always True:
if age == 13 or 14 or 15:

# RIGHT:
if age in (13, 14, 15):
if age == 13 or age == 14 or age == 15:
  1. A It's correct code
  2. B or has higher precedence than ==
  3. C 14 and 15 are evaluated as standalone truthy values, so the condition is always True
  4. D == can't be used with or

Answer: C — 14 and 15 are evaluated as standalone truthy values, so the condition is always True

The condition parses as (age == 13) or (14) or (15). The bare numbers 14 and 15 are truthy on their own, so the whole condition is ALWAYS True. Correct: age in (13, 14, 15) or repeat the comparison.

  • One of the most common logic bugs in beginner Python code.

Q22. hard

Why is the ORDER of this condition important? if x != 0 and 10 / x > 2:

x = 0
if x != 0 and 10 / x > 2:   # safe
    ...
# if 10 / x > 2 and x != 0:  # crashes when x == 0!
  1. A It isn't - order never matters with and
  2. B and evaluates left to right and STOPS at the first False, so 10/x never runs when x is 0 - preventing ZeroDivisionError
  3. C Python evaluates the right side first
  4. D x != 0 is slower so it should be last

Answer: B — and evaluates left to right and STOPS at the first False, so 10/x never runs when x is 0 - preventing ZeroDivisionError

Short-circuiting: if x != 0 is False, Python skips the right side entirely. Reversed (10 / x > 2 and x != 0), a zero x would crash with ZeroDivisionError before the guard is reached.

  • Use the same trick with None: if obj is not None and obj.value > 5

Short-circuit evaluationGuard conditions

Q23. hard

not (a and b) is always equal to:

a, b = True, False
print(not (a and b))       # True
print(not a or not b)      # True - same
  1. A not a and not b
  2. B not a or not b
  3. C a or b
  4. D not a and b

Answer: B — not a or not b

De Morgan's law: negating an AND turns it into an OR of negations. 'Not (rich and famous)' means 'not rich OR not famous'. Similarly, not (a or b) == not a and not b.

Q29. hard

What is the output of: print(bool([]) == bool(""))

print(bool(""))    # False
print(bool({}))    # False
print(bool(0))     # False
  1. A True
  2. B False
  3. C Error
  4. D None

Answer: A — True

Both an empty list and an empty string are falsy: bool([]) is False and bool("") is False, and False == False is True. All empty containers share the same truthiness.
