Q1. easy

What is a module in Python?

  1. A A .py file whose functions/variables you can import and reuse
  2. B A type of loop
  3. C A compressed archive
  4. D A class method

Answer: A — A .py file whose functions/variables you can import and reuse

Any Python file is a module. import makes its functions, classes and variables available in your code - the basic unit of code reuse.

Q2. easy

After 'import math', how do you call its square root function?

import math
print(math.sqrt(16))   # 4.0
print(math.pi)          # 3.141592653589793
  1. A math.sqrt(16)
  2. B sqrt(16)
  3. C math->sqrt(16)
  4. D import sqrt(16)

Answer: A — math.sqrt(16)

Plain import binds the MODULE name - you access contents with the dot: math.sqrt(16). Bare sqrt(16) only works after 'from math import sqrt'.

Q3. easy

What does 'from math import sqrt' let you write?

from math import sqrt, pi

  1. A sqrt(16) - directly, without the math. prefix
  2. B math.sqrt(16) only
  3. C Nothing - it's invalid
  4. D sqrt.math(16)

Answer: A — sqrt(16) - directly, without the math. prefix

from-import copies a specific name into your file's namespace: sqrt(16) works directly. The rest of math stays unimported (math.pi would be a NameError).

Q6. easy

What does random.randint(1, 6) return?

  1. A A random integer from 1 to 6, BOTH ends included - like a dice roll

  3. C A random float
  4. D Always 6

Answer: A — A random integer from 1 to 6, BOTH ends included - like a dice roll

Q7. easy

Which picks ONE random item from a list?

import random
winner = random.choice(["Ana", "Ben", "Cy"])
print(winner)
  1. A random.choice(items)
  2. B random.pick(items)
  3. C items.random()
  4. D random.one(items)

Answer: A — random.choice(items)

random.choice(sequence) returns one random element. Related: random.sample(items, 3) picks 3 without repeats; random.shuffle(items) reorders the list in place.

Q5. medium

Why is 'from math import *' discouraged?

# unclear:
from math import *
print(floor(2.7))    # where's floor from?

# clear:
import math
print(math.floor(2.7))
  1. A It dumps EVERY name into your file - unclear origins, and it can silently overwrite your own variables
  2. B It's slower to run
  3. C It's a syntax error
  4. D It only imports half the module

Answer: A — It dumps EVERY name into your file - unclear origins, and it can silently overwrite your own variables

Star imports pollute the namespace: readers can't tell where a function came from, and two star imports can clash (both defining e.g. sqrt). Import what you need, explicitly.

Q15. hard

What is the purpose of: if __name__ == "__main__": main()

# helpers.py
def greet(): ...

if __name__ == "__main__":
    greet()   # runs only via: python helpers.py
              # NOT when: import helpers
  1. A Run main() only when the file is executed DIRECTLY - not when it's imported by another file
  2. B Declare the program's name
  3. C Make the file importable at all
  4. D It's required in every Python file

Answer: A — Run main() only when the file is executed DIRECTLY - not when it's imported by another file

Python sets __name__ to "__main__" in the file being run, but to the module's name when imported. The guard lets a file be BOTH a runnable script AND an importable library - imports get the functions without side effects.

  • A favorite interview question - know this one cold.

Q16. hard

print("loading!") sits at the TOP of helpers.py (outside any function). What happens on 'import helpers'?

# helpers.py
print("loading!")     # runs on import!
def greet(): ...

# main.py
import helpers   # prints: loading!
import helpers   # (cached - nothing prints)
  1. A It prints 'loading!' - top-level code RUNS at import time (but only on the first import)
  2. B Nothing - imports never execute code
  3. C SyntaxError
  4. D It prints on every import statement, even repeated ones

Answer: A — It prints 'loading!' - top-level code RUNS at import time (but only on the first import)

Importing EXECUTES the module top to bottom - defs create functions, and loose statements run. Python caches modules, so a second 'import helpers' does NOT re-run it. This is why the __main__ guard matters.

Q23. hard

Where does Python LOOK for modules when you import?

import sys
print(sys.path)
  1. A The script's folder, then the paths in sys.path (standard library, installed packages)
  2. B The whole hard drive
  3. C Only the standard library
  4. D The internet

Answer: A — The script's folder, then the paths in sys.path (standard library, installed packages)

Python walks sys.path in order: the running script's directory first, then standard library locations, then site-packages (pip installs). This is why a local file named random.py can SHADOW the real random module - a classic bug!

  • Never name your files math.py, random.py, string.py...

Q27. hard

What is a circular import?

  1. A a.py imports b.py while b.py imports a.py - one gets a half-loaded module and often crashes
  2. B Importing the same module twice
  3. C Importing with a loop
  4. D A pip feature

Answer: A — a.py imports b.py while b.py imports a.py - one gets a half-loaded module and often crashes

When two modules import each other, Python starts loading a, pauses to load b, which asks for a - but a is only half-executed, so names may be missing (ImportError/AttributeError). Fix: restructure, move shared code to a third module, or import inside functions.
